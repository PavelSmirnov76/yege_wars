# Supabase: база данных проекта

Папка содержит всё, что относится к базе данных платформы:

- `migrations/` — SQL-миграции схемы. Применяются строго по порядку имён файлов:
  1. `20260917120000_schema.sql` — расширения, таблицы, индексы, триггеры регистрации;
  2. `20260917120001_rls.sql` — row level security и привилегии;
  3. `20260917120002_functions.sql` — функции (RPC) и права на их выполнение.
- `seed/` — данные для наполнения (задачи и т.п.);
- `tests/` — локальная проверка миграций.

## Как применить миграции к проекту Supabase

Способ 1 — SQL Editor:

1. Откройте проект на [supabase.com](https://supabase.com) → **SQL Editor**.
2. Вставьте содержимое файлов из `migrations/` и выполните их **по одному, в порядке имён файлов**.

Способ 2 — psql по строке подключения (Session Pooler):

1. В панели проекта нажмите **Connect** и скопируйте строку подключения **Session Pooler** (вида `postgresql://postgres.<ref>:<password>@aws-0-<region>.pooler.supabase.com:5432/postgres`).
2. Выполните из корня репозитория:

```bash
psql "<строка подключения>" \
  -f supabase/migrations/20260917120000_schema.sql \
  -f supabase/migrations/20260917120001_rls.sql \
  -f supabase/migrations/20260917120002_functions.sql
```

## Первый администратор

Регистрация всегда создаёт пользователя с ролью `student`. Роль первому админу
назначается вручную (SQL Editor или psql) после его регистрации в приложении:

```sql
update profiles set role = 'admin' where username = '<логин>';
```

Дальше админ управляет ролями из приложения через RPC `admin_set_role`.

## Локальная проверка

Миграции можно прогнать на локальном PostgreSQL 17 с шимом схемы `auth`
(таблица `auth.users`, функция `auth.uid()`, роли `anon`/`authenticated`/`service_role`):

```bash
bash supabase/tests/run_local.sh
```

## Важно

Схему меняем **только миграциями** (новыми файлами в `migrations/`), а не через
Table Editor или другие разделы UI. Иначе локальная копия, тесты и продакшен
разойдутся, и восстановить единое состояние будет трудно.
