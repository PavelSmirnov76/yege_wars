## Токены

Именование: `TOKEN-{n}-{GROUP}.md` — одна группа на файл. `{GROUP}` — одно
слово без дефисов: `COLOR`, `TYPOGRAPHY`, `SPACING`, `RADIUS`, `BREAKPOINT`,
`TAP`.

Группа — таблица: имя токена, значение, назначение. Имя — то, под которым токен
живёт в коде темы, чтобы его находили поиском. У каждой строки — якорь по имени
токена: `<a id="accent"></a>`.

Ссылка на отдельный токен — на группу с якорем, имя токена рядом. Из
компонента в этой папке: `accent` — [TOKEN-1](TOKEN-1-COLOR.md#accent).
Видимый текст ссылки — id группы (закон,
«Ссылка на артефакт — это id, а не путь»), якорь проверяет скрипт.

Каждый файл темы `lib/app/theme/` несёт метку своей группы (закон, «Код
ссылается на артефакты»). Значение в коде и в токене совпадает. Значение
изменилось — создают новую группу с `supersedes`, старую хоронят.

## Компоненты

Именование: `COMP-{n}-{NAME}.md` — один компонент на файл.

Компонент описывает:

- **варианты** — чем отличаются и когда какой;
- **состояния** — каждое: что видно и когда наступает (обычное, наведение,
  фокус, нажатие, недоступно, загрузка, ошибка — какие у него есть);
- **токены**, которые использует, — ссылками на токены.

Виджет компонента несёт метку `COMP-{n}` (закон, «Код ссылается на
артефакты»).

## Как снимать с построенного

Дизайн-систему уже сделанного снимают с кода: значения — из `lib/app/theme/`,
компоненты — из общих виджетов, по срезу текущего прохода «как построено».
Записывают то, что есть в коде, а не то, каким оно должно быть. Расхождение с
ТЗ — заметкой в `0-vibes/raw/<дата>/`.
