# ENT-18: Сводка прогресса

**Модуль:** [MOD-10](../modules/MOD-10-PROGRESS.md). **Пользователь:** [ENT-2](ENT-2-PROFILE-IN-AUTH.md). **Попытка:** [ENT-11](ENT-11-ATTEMPT-IN-SUBMISSION.md). **Задача:** [ENT-6](ENT-6-PROBLEM-IN-CATALOG.md).

Сводка вычисляется из задач и попыток текущего пользователя при чтении.

## Состав

- `user_id: uuid` — владелец загружаемой сводки, равен текущему `auth.uid()`.
- `by_number` — строки `ege_number: smallint?`, `solved: bigint`,
  `total: bigint`. Номера возрастают, строка с `null` последняя.
- `solved_total: bigint`, `available_total: bigint` — суммы соответствующих
  полей всех строк, включая строку без номера. При пустом списке обе суммы 0.
- `recent_attempts` — до десяти записей `id: uuid`, `task_id: uuid`,
  `task_slug: text`, `task_title: text`, `ege_number: smallint?`,
  `is_correct: boolean`, `created_at: timestamptz`.

## Чтение прогресса

`get_user_progress(p_user_id uuid)` возвращает строки
`{ege_number, solved, total}`. Вызов клиента передаёт id текущего аккаунта.
Обе величины считаются среди `tasks.status = 'published'`, задача решена,
если существует хотя бы одна верная попытка этого пользователя.
`0 <= solved <= total`, у каждой строки `total > 0`.

Пользователь может читать свой прогресс, чужой через эту RPC — только
администратор. Запрещённый вызов отвечает существующим кодом `[forbidden]`.
Экран профиля администратора также запрашивает собственный id.

## Чтение последних попыток

Серверный запрос к `submissions` соединяет задачу через внутреннее соединение
`task:tasks!inner(id,slug,title,ege_number)`, явно фильтрует
`user_id = auth.uid()` и `task.status = published`, сортирует
`created_at desc, id desc`, применяет `limit 10` после фильтров.
Выбираются только перечисленные поля попытки и задачи.

RLS сохраняет существующие права на таблицы. Явный фильтр автора обязателен,
поскольку RLS допускает также некоторые чужие попытки. Статус задачи явно
фильтруется и для администратора. Ответ и код попытки в сводку не входят.

## Обновление и отказы

При каждом входе на экран выполняются оба запроса. Данные считаются
загруженными после успеха обоих. Ошибка любого запроса даёт состояние ошибки
с повтором обоих запросов. Автоматических повторов нет, согласно
[R46](../../0-vibes/prd/PRD.md#r46).

При выходе, смене аккаунта или устаревании запроса его результат не заменяет
сводку нового аккаунта или более нового запроса. После отправки ответа и
возврата на уже созданную ветку профиля выполняется новая загрузка.

Оба запроса только читают. Таблицы и RPC сохраняют существующие сигнатуры.
