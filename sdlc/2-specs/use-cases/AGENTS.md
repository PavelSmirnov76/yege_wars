Именование:
`UC-{n}-ACTOR-{n}-EVT-{n}-ENT-{n}-{OUTCOME}-IN-{MODULE}.md`.

Имя несёт происхождение: главный актор, событие-триггер, главная сущность и
исход основного пути. Листинг сам говорит, кто что сделал с какой сущностью и
чем кончилось.

Каждый id в имени уже существует: UC не выдумывает своего актора, событие и
сущность, а ссылается на живые артефакты. Если какой-то из них потом похоронят,
имя остаётся как есть (закон, «Устарелость выводится, а не записывается»).

## Состав

- **Основание** — ссылки на `R{n}`, бизнес-задачу планирования и модуль.
- **Триггер** — что запускает сценарий.
- **Предусловия**.
- **Пути** — ниже.
- **Постусловия**, общие для всех путей.

## Пути и исходы

Каждая значимая ветка поведения — путь, заголовком H3 с якорем:

```markdown
### <a id="uc-3-p-01"></a>UC-3-P-01 — вход с верным паролем

…

**Исход:** UC-3-O-01 — открыт каталог
```

В пути — условие или ход, который его отличает, и наблюдаемое поведение. У
пути ровно один исход, у исхода ровно один путь, оба того же UC, и номер
исхода равен номеру пути. `{nn}` — двузначный номер с `01`.

Отдельный путь получают основной успех, отказ проверки, другой бизнес-исход,
отказ сервера, восстановление. Не каждое поле, запрос или экран: вариации
значений — параметры тестов, а не пути.

Путь — единица проверки: тесты несут метку пути (закон, «Код ссылается на
артефакты»), сводка показывает вердикт по каждому пути. Путь без теста —
непроверенный.
