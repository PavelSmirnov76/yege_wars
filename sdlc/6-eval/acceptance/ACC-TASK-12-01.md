### 1. Обновление при повторном входе через маршрут

Нарушен [UC-41-P-01](../../2-specs/use-cases/UC-41-ACTOR-2-EVT-25-ENT-18-PROGRESS-SHOWN-IN-PROGRESS.md#uc-41-p-01)
и [R55](../../0-vibes/prd/PRD.md#r55). Обновление подключено только к выбору
пункта навигации в `lib/app/router/app_shell.dart`, условие `index == 2`.
`StatefulShellRoute.indexedStack` сохраняет экран и наблюдаемый провайдер.
Повторный вход через сам маршрут пропускает этот callback.

Воспроизведение адресным widget-тестом с настоящим роутером приложения

1. Открыть `router.go('/profile')`, сводка fake-репозитория 0 из 0.
2. Перейти `router.go('/task/e24-longest-run')`.
3. Изменить результат репозитория на номер 24, solved 1, total 2.
4. Выполнить `router.go('/profile')` без нажатия навигационной кнопки.

Ожидание — новый вызов репозитория и 1 из 2. Наблюдение — вызов остался
один, экран показал старые 0 из 0, расположение маршрута уже `/profile`.

Исправить обновление при каждом входе в ветку, включая повторный вход
маршрутом и возврат через историю. Сохранить обновление по повторному
нажатию выбранного пункта. Добавить регрессионный тест с уже созданной
веткой, а для истории проверить поддерживаемый приложением путь возврата.

### 2. Ошибка одного запроса ждёт второй

Нарушен [UC-41-P-04](../../2-specs/use-cases/UC-41-ACTOR-2-EVT-25-ENT-18-PROGRESS-SHOWN-IN-PROGRESS.md#uc-41-p-04)
и [R46](../../0-vibes/prd/PRD.md#r46).
`ProgressRepositoryImpl.getProgress` в
`lib/features/profile/data/progress_repository.dart` использует
`Future.wait` с обычным ожиданием завершения всех запросов.

В адресной проверке `source.progress` сразу завершился ошибкой,
`source.attempts` остался на незавершённом Completer. После обработки
очереди async-событий future репозитория оставался pending. Лишь после
завершения второго запроса он вернул `Err<ProgressSummary>`.

Обеспечить переход к ошибке сразу при отказе любого запроса. Для
существующего `Future.wait` подходит `eagerError: true`. Повтор должен
запускать оба запроса, поздние результаты предыдущей загрузки должны
сохранять изоляцию нового состояния. Добавить детерминированный тест
«ошибка + второй pending» и убедиться, что Future завершается ошибкой
до разрешения pending-запроса.
