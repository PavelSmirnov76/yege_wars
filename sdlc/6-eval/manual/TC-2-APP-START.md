# TC-2: Запуск приложения — с параметрами сборки и без них

**Цель:** установить, что сборка с параметрами тестового проекта запускается
и ведёт себя по состоянию входа, а сборка без параметров показывает экран
«Приложение не сконфигурировано» с причиной и дальше не пускает.

**Пути UC:** [UC-12-P-01](../../2-specs/use-cases/UC-12-ACTOR-1-EVT-10-ENT-5-APP-STARTED-IN-CONFIG.md#uc-12-p-01), [UC-12-P-02](../../2-specs/use-cases/UC-12-ACTOR-1-EVT-10-ENT-5-APP-STARTED-IN-CONFIG.md#uc-12-p-02).

**Приоритет:** средний — без параметров сайт не публикуется, экран нужен
при локальной сборке.

## Предусловия

- Сборка A — `main` по `README.md`, раздел «Локальная сборка с тестовым
  проектом». Сборка B — та же команда без четырёх `--dart-define`. Каждая
  раздаётся локальным сервером на `http://localhost:8080/`.
- Браузер без сохранённой сессии сайта.
- Каждый экран — на 360 и 1440 px (`6-eval/manual/AGENTS.md`, «Вид экрана»).

## Шаги

| № | Шаг и входные данные | Ожидаемый результат | Путь |
|---|---|---|---|
| 1 | Сборка A: открыть `http://localhost:8080/` | Заставка, затем экран входа «Вход» | UC-12-P-01 |
| 2 | Сборка B: открыть `http://localhost:8080/` | Без навигации, по центру: заголовок «Приложение не сконфигурировано», под ним «Не заданы SUPABASE_URL и SUPABASE_ANON_KEY. Соберите приложение с параметрами --dart-define.»; экрана входа нет | UC-12-P-02 |
| 3 | Сборка B: открыть `http://localhost:8080/#/login` | Тот же экран «Приложение не сконфигурировано» | UC-12-P-02 |

После кейса на сервере снова сборка A.
