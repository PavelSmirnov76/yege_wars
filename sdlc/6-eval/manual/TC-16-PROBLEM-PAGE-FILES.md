# TC-16: Страница задачи — условие, файлы и неизвестный адрес

**Цель:** проверить реальное открытие задачи и работу с её файлами.
**Пути UC:** [UC-15-P-01](../../2-specs/use-cases/UC-15-ACTOR-4-EVT-12-ENT-6-PROBLEM-SHOWN-IN-CATALOG.md#uc-15-p-01), [UC-15-P-02](../../2-specs/use-cases/UC-15-ACTOR-4-EVT-12-ENT-6-PROBLEM-SHOWN-IN-CATALOG.md#uc-15-p-02).
**Приоритет:** высокий — чтение условия и получение входных данных.
**Дизайн:** [FIG-20](../../3-design/FIG-20-PROBLEM.md),
[COMP-16](../../3-design/design-system/COMP-16-MARKDOWN.md),

## Предусловия

- Локальная сборка main с yege_wars_dev по README.md, localhost:8080.
  Вход учеником TEST_LOGIN2_* из supabase/.env.dev.local: штатной формой
  либо кнопкой тестового входа, если сборка настроена на этого ученика.
  Хэш и способ входа записать; доступы и токены не выводить.
- Тестировщик — Luna. Новая вкладка на каждую ширину: 1440×900 desktop;
  360×800 с mobile/touch, мобильным user agent и до Flutter:
  `Object.defineProperty(navigator, 'platform', {get: () => 'Linux armv8l'});`.
  Это вся имитация: ответы API в этом кейсе настоящие.
- По tasks_public выбрать опубликованную задачу T с файлами. Записать slug,
  название, номер, сложность, наличие источника и имена файлов. Если T
  отсутствует — BLOCKED с недостающими данными; не создавать контент.
  Условие и файлы сверять по ответам tasks_public/task_files именно T,
  файлы — по sort_order из запроса. Эталонные ответы/решения не запрашивать.
- Для неизвестного адреса выбрать slug `tc-missing-<дата>` и убедиться
  чтением tasks_public, что его нет. Наличие скрытой задачи не требуется:
  этот шаг доказывает неизвестный адрес, а не RLS скрытой задачи.
- Код и ответ не редактировать, «Запустить» и «Отправить ответ» не нажимать.
  Clipboard перед копированием сохранить локально без вывода и затем
  восстановить. Если браузер не даёт прочитать clipboard или скачать файл,
  соответствующий шаг BLOCKED; наличие кнопки не заменяет действие.

## Шаги

| № | Действие | Ожидаемый результат |
|---|---|---|
| 1 | Открыть T из каталога и дождаться загрузки; просмотреть условие до конца | Адрес /#/task/<slug T>, в AppBar название T; номер/«Без номера», сложность, Markdown и источник соответствуют данным. На 1440 вкладка «Задача»: условие и код в колонках 3:2, попыток справа нет. На 360 сначала «Условие», код отдельно. Длинный AppBar может сокращаться многоточием, полное название доступно в semantics; обрезание самого условия не допускается |
| 2 | Открыть вкладки с попытками и затем «Файлы» через строку вкладок | На 1440 попытки во вкладке «Попытки», на 360 — ниже редактора во вкладке «Код». Последние вкладки доступны собственной горизонтальной прокруткой. Файлы перечислены в серверном порядке, имя и размер соответствуют данным; чужие ответы/решения для этого шага не открывать |
| 3 | Раскрыть первый файл F; нажать «Копировать» | «Первые строки»: не более 10 строк содержимого, строка не длиннее 10 000 символов; многоточие допускается как признак усечения. Размер: до 1024 — байты, иначе килобайты (до 100 — один знак после запятой, далее округлённо). Clipboard равен полному content F, а не preview; сообщение «Файл скопирован в буфер обмена» |
| 4 | Нажать «Скачать» у F; проверить скачанный файл во временной папке | Имя равно filename F, UTF-8-содержимое равно полному content F. Для сравнения достаточно результата равенства/длины, содержимое в журнал не копировать. После прямого открытия того же /#/task/<slug T> и reload задача снова доступна |
| 5 | Открыть неизвестный slug; нажать «Повторить» | «Задача не найдена или ещё не открыта.» и «Повторить». Нажатие вызывает новый запрос того же slug; сообщение остаётся, условие прежней T не показывается. Авторизация и навигация остаются доступны |

## Вид и доказательства

На каждой ширине — по одному кадру на шаг в его итоговом состоянии;
если действие короткое, снять его результат, а не промежуточный клик.
В журнале: ожидаемое/наблюдаемое, slug T и неизвестный slug, метаданные F,
результаты сравнений clipboard и скачивания, число запросов до/после повтора.
Условие не должно перекрываться навигацией; прокрутка файла или вкладок
не должна прокручивать всю страницу вбок. Измерить реальные тап-цели
«Копировать», «Скачать», «Повторить» на каждой ширине: минимум 44×44.
Не повторять матрицу плотности чипов каталога.

Не публиковать содержимое clipboard, ответы попыток, код решений, токены
и тела запросов с секретами. Вкладку с попытками снимать только если там
нет реальных ответов; иначе записать ограничение доказательства и использовать
клиентский кейс отправки/попыток на синтетических данных этого среза.

После кейса восстановить clipboard, удалить только собственный скачанный
файл, закрыть свои вкладки. Данные Supabase не менялись.
Вердикт пишет тестировщик по факту: PASS, FAIL или BLOCKED с причиной.
