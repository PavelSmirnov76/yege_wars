## Предусловия и границы

2026-11-04 владелец выбрал для этого среза подмены API без записи попыток.

- Окружение, вход, обе ширины и mobile platform — по
  [TC-16](TC-16-PROBLEM-PAGE-FILES.md). Тестировщик — Luna.
- Начальный скрипт из [TC-17](TC-17-PROBLEM-PAGE-STATES.md), режим good;
  открыть /#/task/tc-problem-page. Подмена живёт только в своей вкладке.
  Для каждой ширины — новая загрузка и пустые синтетические попытки.
- В window.__taskCase меняются только mode, submitMode и delayMs.
  Режим submitMode выбирает ответ mock RPC независимо от введённого текста:
  correct — верный, wrong — неверный, rate/missing/error/offline — ошибки.
  Это проверка реакции UI на контракт, а не алгоритма сравнения в БД.
- Отправлять только вымышленные маркеры `tc_wrong` и `tc_correct`.
  Условие синтетическое, формат string, реальных эталонов и решений нет.
  Редактор содержит безопасный комментарий `# tc_ui_marker`.
- Все submit_solution, сохранения черновиков и прочие записи REST
  перехвачены; настоящий вызов записи — нарушение предусловия, остановить
  кейс. blockedWrites должен остаться 0. Публикацию не нажимать.
- На 1440 форма в правой колонке «Задачи», попытки — во вкладке «Попытки»;
  на 360 и форма, и попытки во вкладке «Код». Не искать общий для обеих
  раскладок заголовок «Мои попытки» на desktop: там его заменяет вкладка.

## Шаги

| № | Действие | Ожидаемый результат |
|---|---|---|
| 1 | Открыть форму и место списка попыток; затем вернуться к форме | Поле «Ответ», подсказка строкового формата «Точно как требует условие: регистр, запятые и пробелы важны», кнопка «Отправить ответ». В списке «Попыток пока не было». При отсутствии запуска нет кнопки «Взять из вывода» и нет вердикта |
| 2 | Отправить пустое поле кнопкой, затем только пробелы через Enter | После каждого действия «Введите ответ перед отправкой.» под кнопкой; вердикта и блока публикации нет. calls.submit не изменился, синтетических попыток нет. Активная кнопка при пустом поле сама по себе не дефект |
| 3 | submitMode = 'wrong', delayMs = 1500. Ввести `  tc_wrong  `, нажать «Отправить ответ» один раз | Пока RPC ожидает — «Отправляю…», кнопка недоступна; после — «Неверно. Попробуй ещё раз» с красным значком/подложкой, без блока публикации. Ровно один новый submit, lastSubmit.p_answer равно tc_wrong без краёв, p_code равен комментарию редактора, p_task_id — id fixture. В attempts одна неверная строка |
| 4 | submitMode = 'correct', delayMs = 0. Ввести `  tc_correct  `, отправить через Enter; нажать «Не сейчас» | «Верно!» с зелёным значком/подложкой и блок «Задача решена!» с пояснением и двумя кнопками. Один новый submit, правильные поля lastSubmit, в attempts новая верная строка. «Не сейчас» скрывает предложение публикации; вердикт остаётся, RPC публикации не вызывается |
| 5 | Не перезагружая вкладку, по очереди submitMode = 'rate', 'missing', 'error', 'offline'; для каждого отправить непустой тестовый маркер | Соответственно: «Слишком много отправок, подождите минуту.»; «Задача не найдена или недоступна.»; «Ошибка при работе с данными. Попробуйте позже.»; «Нет соединения с сервером. Проверьте интернет.». Ошибка под кнопкой, прошлого вердикта/предложения публикации нет, форма снова доступна. Для каждого один вызов submit, attempts по-прежнему две; ошибки не добавляют строки |
| 6 | Открыть список попыток, сверить с window.__taskCase.attempts | Ровно две строки, новая верная первой: тестовый ответ, значок вердикта, время ДД.ММ ЧЧ:ММ в локальном часовом поясе. У верной переключатель «Опубликовано» выключен; у неверной его нет. На 360 длинный ответ/время не перекрывают друг друга. Обновление клиента проверяется по запросу attempts и UI, одной записи в массиве hook недостаточно |
| 7 | Новая загрузка с mode = 'attempts-error'; открыть список попыток. Сохранить calls.attempts, изменить mode на good и нажать «Повторить» без reload | Вместо списка сообщение об ошибке и «Повторить», а не «Попыток пока не было». Условие и редактор доступны. После нажатия новый запрос attempts и пустой список с «Попыток пока не было»: новая вкладка сбросила fixture, это не проверка сохранности настоящих попыток |

## Доказательства и завершение

Полностью пройти на каждой ширине. Кадры — пустые попытки, пустой ответ,
отправка в ожидании, неверный ответ, верный с блоком публикации, после
«Не сейчас», каждая из четырёх ошибок, две попытки, сбой списка и его повтор.
Если несколько состояний одного шага нельзя показать одним кадром —
отдельный кадр на состояние. Скриншоты только с вымышленными данными.

В журнале — для каждого шага ожидаемое/наблюдаемое, прирост calls/replaced,
lastSubmit только с синтетическими маркерами и число попыток. Для времени
достаточно сравнения UI со временем fixture в локальном часовом поясе;
не закреплять конкретную дату. Измерить реальные тап-цели кнопок отправки,
«Не сейчас», «Опубликовать решение», «Повторить»: минимум 44×44.
Клик публикации в этот кейс не входит. Проверить, что текст ошибок и вердикт
читаются целиком, навигация не перекрыта, вся страница вбок не прокручивается.

Кейс не доказывает серверную нормализацию/сравнение, лимит 10 в минуту,
сохранение в БД, изоляцию чужих попыток, публикацию или обновление реальной
статистики каталога. PASS относится только к описанным клиентским действиям.
Заголовки авторизации, реальные ответы и код решений не выводить.
В конце снять hook через restore и закрыть свои вкладки; Supabase не менялся.
Вердикт — по факту, отсутствие перехвата/средства проверки — BLOCKED.
