# TC-15: Каталог — области нажатия чипов и краевые клики

**Цель:** проверить минимальную область нажатия трёх групп чипов каталога
в обоих состояниях, реальные клики у границ и раскладку после увеличения
настольной плотности до стандартной.

**Путь UC:** [UC-14-P-02](../../2-specs/use-cases/UC-14-ACTOR-4-EVT-11-ENT-6-PROBLEMS-LISTED-IN-CATALOG.md#uc-14-p-02).

**Приоритет:** высокий — подтверждённый брак против минимума области нажатия.

**Дизайн:** [TOKEN-6](../../3-design/design-system/TOKEN-6-TAP.md),
[FIG-11](../../3-design/FIG-11-CATALOG.md),
[COMP-4](../../3-design/design-system/COMP-4-NAVIGATION.md).

## Предусловия

- Локальная release-сборка проверяемой ветки по README, тестовый проект
  `yege_wars_dev`, `http://localhost:8080/`. Записать ветку и хэш сборки.
  Ученик `TEST_LOGIN2_USERNAME` / `TEST_LOGIN2_PASSWORD` из
  `supabase/.env.dev.local`; вход настоящей формой или штатным тестовым
  входом, настроенным на этого ученика. Доступы и токены не записывать.
- Нет подмен API и изменений базы. Каталог успешно загружен, есть минимум
  два разных доступных номера КЕГЭ. Нет данных/входа — BLOCKED с причиной;
  не создавать задачи и попытки ради кейса.
- Полностью пройти кейс в новой вкладке на 1440×900 с настольной платформой
  и на 360×800 с mobile/touch и Android user agent. До Flutter на mobile
  передать в initScript:
  `Object.defineProperty(navigator, 'platform', {get: () => 'Linux armv8l'});`.
  При полной перезагрузке повторить эту установку. Зафиксировать
  `innerWidth/innerHeight`, platform, UA и maxTouchPoints; изменение одной
  ширины не заменяет мобильную платформу.
- На 1440 включить семантику штатной кнопкой Flutter Enable accessibility;
  на 360 использовать штатное включение, не подменять код приложения.
  Если измерить и проверить реальный hit area невозможно — BLOCKED;
  размер цветной заливки не заменяет область нажатия.

Подстановки: **E** и **F** — первые два разных номера доступного ряда,
записать значения. Проверяемые чипы: E, F, «Простая», «Средняя», «Сложная»,
«Не начата», «Есть попытки», «Решено». Поиск пустой.

## Как проверять область

Для каждого чипа получить runtime-прямоугольник интерактивной области
из Flutter semantics; записать x/y/ширину/высоту. Обе стороны не меньше
44 логических пикселей. Внешний контейнер/текст/заливка не подходят как
единственное доказательство hit area.

До выбора и после него заново получать rect: галочка, кнопка сброса и
перенос строк могут сдвинуть чип. Реальным нажатием по горизонтальному
центру на y верхнего края + 0.5 выбрать чип; затем по центру на y нижнего
края − 0.5 выбранного чипа снять его. Записать координаты и состояние
ДО→ПОСЛЕ каждого нажатия. Успешный вызов инструмента без изменения состояния
не доказывает попадание.

Проверяется только один выбранный фильтр за раз. После снятия чипа
поиск пуст, остальные чипы не выбраны, сброс скрыт. Ошибка реального запроса
не считается успешным отбором; восстановить предусловие или записать
BLOCKED/FAIL по наблюдению. Число реальных карточек заранее не фиксируется.

## Шаги

| № | Действие | Ожидаемый результат |
|---|---|---|
| 1 | После входа явно открыть `/#/`, дождаться каталога; записать E/F, платформу и исходные rect всех восьми чипов | Поиск пуст, фильтры сняты, сброс скрыт; все измеренные области не меньше 44×44 |
| 2 | Для E, затем F выполнить проверку краевых кликов выше, каждый выбор снять до следующего | У верхней границы выбирается именно нажатый номер; rect выбранного чипа тоже не меньше 44×44; нижняя граница снимает его, сброс скрывается. Карточки после выбора относятся к выбранному номеру, после снятия возвращается исходный каталог |
| 3 | По очереди проверить таким же способом «Простая», «Средняя», «Сложная» | Выбирается соответствующая сложность; её область не меньше 44×44; второй краевой клик снимает выбор. Результат соответствует условию либо показано «По этим условиям задач нет»; после снятия каталог восстанавливается |
| 4 | По очереди проверить «Не начата», «Есть попытки», «Решено» | Выбирается именно нажатый чип прогресса; его область не меньше 44×44; второй краевой клик снимает выбор. Допустимо пустое состояние для прогресса, которого нет у ученика; после снятия возвращается исходный список |
| 5 | Обычным нажатием выбрать E, затем F без ручного снятия E; выбрать «Простая», затем «Средняя»; «Не начата», затем «Решено» | В каждой группе выбран только последний чип; группы сочетаются. На обеих ширинах все выбранные чипы/сброс доступны, перенос не перекрывает надписи |
| 6 | Нажать «Сбросить фильтры» | Выбор всех чипов снят, сброс скрыт, исходный список вернулся; поиск пуст. Область сброса не меньше 44×44 |
| 7 | Прокрутить отдельно ряд номеров до конца и обратно, затем список карточек; на mobile просмотреть все строки фильтров | Прокручивается номерный ряд, а не вся страница вбок. Ничего не обрезано и не налезает; навигация слева на desktop, снизу на mobile, «Каталог» выбран, «Админки» нет |

## Доказательства и завершение

На каждой ширине снять каждый шаг. Для шагов 2–4 — выбранное состояние и
снятый выбор каждого проверенного чипа; каждый кадр с подписью. В журнале
матрица: подпись чипа, rect без выбора/с выбором, две координаты, состояния
ДО→ПОСЛЕ, ожидаемое против фактического. Не выдавать semantics-размер за
доказательство клика без реального нажатия.

Не требовать ровно 44 или ровно 48; контракт TOKEN-6 — минимум 44.
Видимая заливка чипов может быть меньше интерактивной области. Полный
поиск/состав результатов отдельно проверяет
[TC-14](TC-14-CATALOG-FILTERS.md), синтетические состояния —
[TC-12](TC-12-CATALOG-STATES.md).

Сетевые наблюдатели, если ставились, убрать; собственные вкладки закрыть.
Не записывать user_id, заголовки, доступы, ответы задач или решения.
Данные Supabase и код продукта не менялись. Журнал, фактические результаты
и одну строку `**Вердикт:** PASS`/`FAIL`/`BLOCKED` заполнить после прогона.
