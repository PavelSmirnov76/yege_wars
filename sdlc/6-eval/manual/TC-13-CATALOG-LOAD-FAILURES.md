# TC-13: Каталог — сбои загрузки, повтор и отсутствие номеров

**Цель:** проверить ошибку каждого источника каталога, восстановление через
«Повторить» и работу каталога при отдельном сбое списка номеров КЕГЭ.

**Пути UC:** [UC-14-P-02](../../2-specs/use-cases/UC-14-ACTOR-4-EVT-11-ENT-6-PROBLEMS-LISTED-IN-CATALOG.md#uc-14-p-02), [UC-14-P-04](../../2-specs/use-cases/UC-14-ACTOR-4-EVT-11-ENT-6-PROBLEMS-LISTED-IN-CATALOG.md#uc-14-p-04).

**Приоритет:** высокий — сбой не должен выглядеть как пустой каталог.

**Дизайн:** [FIG-11](../../3-design/FIG-11-CATALOG.md),
[COMP-12](../../3-design/design-system/COMP-12-ERROR-RETRY.md),
[TOKEN-6](../../3-design/design-system/TOKEN-6-TAP.md),
[TOKEN-7](../../3-design/design-system/TOKEN-7-COLOR.md).

## Предусловия и механизм сбоя

- Сборка `main` с `yege_wars_dev`, `http://localhost:8080/`;
  ученик `TEST_LOGIN2_*` из `supabase/.env.dev.local`.
  Реальный каталог до имитации загружается и содержит задачи с номером.
- Полный кейс на 1440×900 и 360×800. На 360 mobile/touch, мобильный
  user agent и переопределение `navigator.platform` до запуска Flutter,
  как в [TC-11](obsolete/TC-11-CATALOG-FILTERS.md), «Предусловия и подстановки»;
  на 1440 — настольная платформа. Хэш сборки, размеры и платформу — в раунд.
- Использовать начальный скрипт из
  [TC-12](TC-12-CATALOG-STATES.md), раздел «Начальный скрипт».
  Для каждого режима отдельная полная загрузка `/#/` через `initScript`
  с указанным `mode`; вход настоящим учеником сохранить.
  Не включать общий офлайн: иначе можно проверить сбой авторизации вместо
  сбоя каталога. Подменяется только один маршрут каталога.
- Режимы `tasks-error`, `stats-error`, `attempts-error`, `numbers-error`
  возвращают HTTP 503 с обычным кодом PostgREST `XX000` только на
  выбранном маршруте. Остальные запросы идут в реальный тестовый проект.
  `tasks-offline` отклоняет только запрос списка сетевой ошибкой.
- До каждого режима убедиться, что страница вошедшего пользователя открыта.
  Перенаправление на вход — не подтверждение проверяемой ошибки; записать
  причину, восстановить предусловие или поставить `BLOCKED`.
  Если счётчик `replaced` нужного маршрута равен нулю, сбой не воспроизведён.

## Шаги

| № | Шаг и входные данные | Ожидаемый результат | Путь |
|---|---|---|---|
| 1 | Загрузить каталог с режимом `tasks-error`; дождаться завершения запросов и проверить `replaced.tasks` | Вместо списка — «Ошибка при работе с данными. Попробуйте позже.» и «Повторить»; нет «Задач пока нет» и «По этим условиям задач нет». Поиск, чипы и навигация остаются на экране | UC-14-P-04 |
| 2 | Сохранить значения `calls`; выполнить `window.__catalogCase.mode = 'real'` без перезагрузки, нажать «Повторить» | Новый запрос списка и рост `calls.tasks`; ошибка сменяется реальными карточками, «Повторить» исчезает. Само переключение режима без нажатия не считается проверкой кнопки | UC-14-P-04 |
| 3 | Повторить шаги 1–2 с режимом `stats-error` | `replaced.stats > 0`; та же ошибка и повтор, после повтора — реальные карточки. Сбой статистики не подменён нулевыми процентами или пустым каталогом | UC-14-P-04 |
| 4 | Повторить шаги 1–2 с режимом `attempts-error` | `replaced.attempts > 0`; та же ошибка и повтор, после повтора — реальные карточки. Сбой собственных попыток не превращает все задачи в не начатые | UC-14-P-04 |
| 5 | Повторить шаги 1–2 с режимом `tasks-offline` | `replaced.tasks > 0`; вместо списка — «Нет соединения с сервером. Проверьте интернет.» и «Повторить». После снятия имитации и повтора — реальные карточки; вход не теряется | UC-14-P-04 |
| 6 | Новая полная загрузка с режимом `numbers-error`; проверить счётчики и интерфейс | `replaced.numbers > 0`, подмен других маршрутов нет; чипов «№ N» нет. Реальные карточки, поиск, сложность и прогресс доступны; ошибки каталога и «Повторить» нет | UC-14-P-02 |
| 7 | Не перезагружая страницу, выбрать сложность имеющейся карточки, затем снять её; ввести часть её названия, затем очистить поиск | Каталог отбирает реальные задачи по сложности и поиску и возвращается к исходному списку. Отсутствие номеров не мешает остальным фильтрам; при условии видна «Сбросить фильтры» | UC-14-P-02 |
| 8 | Закрыть вкладку с подменой; открыть чистую вкладку сборки без скрипта и войти учеником | Обычный каталог загружается, чипы номеров снова видны. Нельзя проверять восстановление номеров одним нажатием «Повторить»: при их отдельном сбое такой кнопки нет | UC-14-P-02 |

## Вид и доказательства

На каждой ширине снять ошибку и восстановленный каталог для каждого
режима отдельно, а также каталог без номеров и с выбранным фильтром.
Ошибки — по центру по COMP-12; текст целиком, «Повторить» доступна и
не обрезана. На 1440 и 360 измерить её видимую высоту и область нажатия:
кнопка темы не ниже 44, тап-цель соответствует TOKEN-6.
Страница не прокручивается вбок, чипы переносятся, навигация не перекрыта.

В журнале для каждого режима: ожидаемый маршрут сбоя, счётчики до/после,
фактическое сообщение, скриншоты и результат повтора. Синтетический ответ
не попадает в нативный сетевой журнал: подтверждение имитации — `replaced`.
Заголовки авторизации, значения доступов и токены не выводить.

После кейса закрыть все вкладки с подменой. Данные Supabase и код продукта
не меняются. Вердикт выставить по фактически пройденным шагам; отсутствие
средства воспроизведения нужного сбоя — `BLOCKED` с причиной.
