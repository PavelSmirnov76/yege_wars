## Предусловия и подстановки

- Сборка `main` по `README.md`, «Локальная сборка с тестовым проектом»,
  на `http://localhost:8080/`. Зафиксировать хэш сборки.
- Ученик `TEST_LOGIN2_USERNAME` / `TEST_LOGIN2_PASSWORD` из
  `supabase/.env.dev.local`; сервер — `yege_wars_dev`.
  Войти штатной формой. Значения доступов, токены и заголовки авторизации
  в раунд не записывать. Подмен ответов API в этом кейсе нет.
- Перед каждым проходом новая вкладка без фильтров. Полностью пройти кейс
  на 1440×900 и 360×800. На 360 включить mobile/touch и мобильный user agent;
  до запуска Flutter переопределить `navigator.platform` в `initScript`
  строкой
  `Object.defineProperty(navigator, 'platform', {get: () => 'Linux armv8l'});`.
  На 1440 оставить настольную платформу. Одного изменения размера окна
  недостаточно. Записать фактические размеры и платформу.
- В тестовом проекте есть опубликованные задачи с номером КЕГЭ.
  Нет данных — `BLOCKED` с указанием недостающих данных; не создавать задачи,
  попытки или ответы ради кейса.

На первом открытии сверить список с ответами запросов текущего ученика:

- `GET /rest/v1/tasks_public`: карточки — `id`, `slug`, `title`,
  `ege_number`, `difficulty`, `tags`; отдельная выборка только `ege_number`
  даёт номера для чипов.
- `POST /rest/v1/rpc/get_task_stats`: `task_id`, `attempted_students`,
  `solved_students`, `solved_percent`.
- `GET /rest/v1/submissions`: только `task_id`, `is_correct`, с фильтром
  `user_id` текущего ученика. Ответы задач и тексты решений не запрашивать.

По этим ответам выбрать задачу **T** с номером; записать её slug и название,
номер **E**, сложность **D**, собственное состояние решения **P**.
**Q** — часть названия T из букв или цифр без знаков синтаксиса PostgREST.
**Z** — `tc_catalog_missing_` с текущей датой: убедиться по названиям,
что этой подстроки нет. Точные количества задач заранее не закрепляются.

Прогресс T: есть своя верная попытка — «Решено»; есть только неверные —
«Есть попытки»; своих попыток нет — «Не начата» в фильтре, без метки на
карточке. «Решили N%» — округлённый `solved_percent`; при
`attempted_students = 0` — «Ещё никто не решал».

## Шаги

| № | Шаг и входные данные | Ожидаемый результат | Путь |
|---|---|---|---|
| 1 | После входа открыть `/#/`, дождаться завершения запросов; просмотреть список прокруткой | «Каталог», поиск с лупой и «Поиск по названию»; номера — только из выборки номеров, по возрастанию и без повторов; шесть чипов сложности и прогресса; «Сбросить фильтры» скрыта. Группы «Задание N» по возрастанию, внутри — порядок названий из отсортированного ответа API; «Без номера», если такие задачи есть, последней | UC-14-P-01, UC-14-P-02 |
| 2 | Сверить T и остальные видимые карточки с ответами API; прокрутить до карточки с длинным названием | Название, сложность, собственный прогресс и доля решивших соответствуют данным. У не начатой задачи нет метки «Не начата». Заголовки и метки читаются, ничего не перекрывается и не обрезается | UC-14-P-01 |
| 3 | Навести на T на 1440, затем нажать карточку; на 360 — коснуться | Отклик карточки в пределах скругления; адрес `/#/task/<slug T>`, заголовок открытой задачи совпадает с T. Глубокая проверка страницы задачи — отдельный срез | UC-14-P-01 |

| 7 | По очереди выбрать «Решено», «Есть попытки», «Не начата»; каждый выбор снять повторным нажатием | Для каждого состояния список соответствует собственным попыткам ученика; при отсутствии совпадений — «По этим условиям задач нет». | 10 | Нажать «Сбросить фильтры», дождаться запросов | Все выбранные чипы сняты; в запросе списка нет номера, сложности и поиска; полный список восстановлен, кнопка сброса скрыта. ## Вид и доказательства

На каждой ширине снять состояние после каждого шага. На 1440 навигация
слева с подписями, на 360 — снизу; выбран «Каталог», у ученика нет
«Админки». Ряд номеров прокручивается внутри себя; вся страница вбок не
прокручивается. На 360 чипы сложности и прогресса переносятся и доступны.
Замерить «Сбросить фильтры» и области нажатия контролов против TOKEN-6;
записать реальные размеры, а не только наличие `minimumSize` в коде.
Высота кнопки сброса темы на компьютере после TASK-10 — не меньше 44.

В журнале — подстановки T/E/D/P/Q/Z, наблюдение против ожидания каждого
шага и обезличенная выписка запросов: путь, параметры отбора, код ответа.
Для шага 7 отдельно указать, по каким данным сверяли прогресс. Совпадение
числа карточек без проверки состава не доказывает правильность отбора.

После кейса убрать сетевые наблюдатели, если ставились, и закрыть вкладку.
Данные проекта не менялись; фактический результат и вердикт пишет только
тестировщик после прогона по `6-eval/manual/AGENTS.md`.
