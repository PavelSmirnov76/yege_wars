# TC-6: Регистрация — успех, ошибки, закрытая регистрация, сбой проверки

**Цель:** установить, что ученик регистрируется по логину и паролю и сразу
входит; что неправильные данные и занятый логин отклоняются; что
переключить регистрацию может только администратор, а экран регистрации
следует флагу и сообщает о сбое проверки.

**Пути UC:** [UC-1-P-01](../../../2-specs/use-cases/UC-1-ACTOR-1-EVT-1-ENT-1-STUDENT-CREATED-IN-AUTH.md#uc-1-p-01), [UC-1-P-02](../../../2-specs/use-cases/UC-1-ACTOR-1-EVT-1-ENT-1-STUDENT-CREATED-IN-AUTH.md#uc-1-p-02), [UC-1-P-03](../../../2-specs/use-cases/UC-1-ACTOR-1-EVT-1-ENT-1-STUDENT-CREATED-IN-AUTH.md#uc-1-p-03), [UC-1-P-04](../../../2-specs/use-cases/UC-1-ACTOR-1-EVT-1-ENT-1-STUDENT-CREATED-IN-AUTH.md#uc-1-p-04), [UC-1-P-05](../../../2-specs/use-cases/UC-1-ACTOR-1-EVT-1-ENT-1-STUDENT-CREATED-IN-AUTH.md#uc-1-p-05), [UC-7-P-01](../../../2-specs/use-cases/UC-7-ACTOR-3-EVT-7-ENT-4-REGISTRATION-SWITCHED-IN-MANAGEMENT.md#uc-7-p-01), [UC-7-P-02](../../../2-specs/use-cases/UC-7-ACTOR-3-EVT-7-ENT-4-REGISTRATION-SWITCHED-IN-MANAGEMENT.md#uc-7-p-02).

**Приоритет:** средний — на боевом регистрация закрыта, учётные записи
заводит владелец.

## Предусловия

- Сборка `main` по `README.md`, раздел «Локальная сборка с тестовым
  проектом», на `http://localhost:8080/`; регистрация на тестовом проекте
  открыта.
- Учётные записи из `supabase/.env.dev.local`: ученик `TEST_LOGIN_USERNAME` /
  `TEST_LOGIN_PASSWORD`, администратор `CONTENT_API_LOGIN` /
  `CONTENT_API_PASSWORD`. API — `SUPABASE_URL` и `SUPABASE_ANON_KEY` оттуда
  же; вход в API — `POST /auth/v1/token?grant_type=password` с почтой
  `<логин>@ege.local`.
- Подстановка — новый логин `tc_reg_<ГГГГММДД>`; если занят — с буквой в
  конце.
- Браузер без сохранённой сессии сайта.
- Каждый экран — на 360 и 1440 px (`6-eval/manual/AGENTS.md`, «Вид экрана»).

## Шаги

| № | Шаг и входные данные | Ожидаемый результат | Путь |
|---|---|---|---|
| 1 | Открыть `http://localhost:8080/`, нажать «Нет аккаунта? Зарегистрируйтесь» | Экран «Регистрация»: поля «Логин» и «Пароль», кнопка «Зарегистрироваться», ссылка «Уже есть аккаунт? Войдите» | UC-1-P-01 |
| 2 | Логин `a-b`, пароль `123`; «Зарегистрироваться» | Под полями: «Логин: 3–20 символов — латиница, цифры и подчёркивание» и «Пароль: не менее 8 символов»; в запросах страницы нет обращения к `/auth/v1/signup` | UC-1-P-02 |
| 3 | Логин — `TEST_LOGIN_USERNAME`, пароль `password123`; «Зарегистрироваться» | Над полями — «Логин уже занят, выберите другой.»; открыт экран регистрации | UC-1-P-03 |
| 4 | API от ученика: `PATCH /rest/v1/app_settings?key=eq.registration_open`, тело `{"value": false}`, заголовок `Prefer: return=representation`; затем `POST /rest/v1/rpc/is_registration_open` | Ответ на `PATCH` — 200 с пустым списком; `is_registration_open` — `true` | UC-7-P-02 |
| 5 | То же от администратора | Ответ на `PATCH` — 200, в списке строка `registration_open` со значением `false`; `is_registration_open` — `false` | UC-7-P-01 |
| 6 | Перезагрузить экран регистрации | Предупреждение «Регистрация закрыта администратором»; поля и кнопка недоступны | UC-1-P-04 |
| 7 | API от администратора: `PATCH` с телом `{"value": true}`; затем `is_registration_open` | `is_registration_open` — `true` | UC-7-P-01 |
| 8 | Перезагрузить экран регистрации, перейти по ссылке «Уже есть аккаунт? Войдите»; отключить сеть браузера (эмуляция офлайн); нажать «Нет аккаунта? Зарегистрируйтесь»; затем включить сеть | Сообщение-ошибка «Не удалось проверить, открыта ли регистрация» | UC-1-P-05 |
| 9 | Перезагрузить экран регистрации; логин из подстановки, пароль `password123`; «Зарегистрироваться» | Открывается «Каталог»; в «Профиле» — этот логин и «Роль: Ученик» | UC-1-P-01 |

Если кейс прервался после шага 5 — вернуть флаг шагом 7: регистрация на
тестовом проекте должна остаться открытой.
