## Метод и отступления

Rect получены из настоящих интерактивных `flt-semantics[role=checkbox]`,
сопоставленных по `aria-label`, через `getBoundingClientRect()`;
состояние — по `aria-checked`. Это rect контролов, а не заливки или текста.
Формат ниже: `(x, y, width, height)`, логические/CSS px, значения без
округления. До каждого нажатия rect читался заново; после выбора и снятия
тоже читался заново.

Все краевые нажатия выполнены настоящим `click_at` Chrome DevTools MCP:
горизонтальный центр, верх + 0.5 для выбора, затем новый горизонтальный
центр, низ − 0.5 для снятия. JS click для чипов не применялся. Успех
устанавливался по ДО→ПОСЛЕ, виду чипа, сбросу и результату каталога.

Штатное включение семантики:
- Desktop: обычный click MCP по «Enable accessibility» не смог нажать
  скрытый элемент (rect −1,−1,1,1); вызван `click()` именно этой штатной
  DOM-кнопки. Семантика появилась; код Flutter не подменялся.
- Mobile: первоначальный DOM `click()` кнопки семантику не включил.
  Затем обычный click MCP по штатной «Enable accessibility» успешно
  включил её. Кадр 23 снят до включения, кадр 24 — после; все измерения и
  краевые нажатия начаты только после успешного включения.

Прокрутка выполнена через штатные DOM scroll-контейнеры Flutter semantics:
`scrollLeft` номерного ряда и `scrollTop` списка карточек. Состояние
проверено runtime-метриками и отдельными кадрами до/после. Это отступление
от ручного жеста прокрутки; отдельность контейнеров и отсутствие
горизонтального смещения страницы проверены непосредственно.

MCP не разрешил сохранить PNG прямо в worktree вне workspace roots.
PNG получены ответом MCP, безопасно декодированы в папку раунда через
shell с `require_escalated`. Каждый сохранённый PNG отдельно просмотрен
через `view_image`. Base64 в журнал не включён.
