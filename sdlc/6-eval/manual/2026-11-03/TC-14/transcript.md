## Отступления и технические ограничения доказательств

- Вместо main использована согласованная постановщиком сборка
  task/TASK-11 ec9cdc4: приёмка задания по RUNBOOK.
- Вместо ручного ввода секретов использована штатная тестовая кнопка;
  во второй новой вкладке восстановилась та же авторизация.
- Desktop fill ввёл «гическая» вместо Q. Первая попытка исправления
  искала input по aria-label, которого у HTML input нет, и получила
  «гическаЛогическая». Эти состояния и HTTP200 не объявляются
  дефектом продукта и не доказывают шаги8/9:
  [12](screenshots/12-desktop-step08.png),
  [13](screenshots/13-desktop-step09.png) — только диагностика.
  После reset обычный input.select(), Backspace и type_text дали
  точный Q; корректный прогон шагов8/9 — PNG14/15.
- На mobile первоначальный click() из script не включал semantics.
  [23](screenshots/23-mobile-step02.png) повторяет исходный экран и
  не доказывает прокрутку шага2. После штатного нажатия
  «Enable accessibility» шаг2 выполнен и снят заново на PNG24.
- Полная прокрутка до конца и финальные desktop-снятия шагов6/7
  досняты после основного прохода. Порядок файлов отражает реальное
  время; эти кадры не представлены как снятые раньше.
- Hover вызван штатным инструментом, но отдельный PNG промежуточного
  эффекта отсутствует; доказательство шага3 — переход и открытая T.
- Точный интервал debounce не замерялся; проверено применение точного
  поиска после паузы более300мс и завершения реального запроса.
- Набор данных не содержит собственных попыток или ненулевой статистики,
  поэтому варианты «Решили N%», непустое «Решено»/«Есть попытки»
  не продемонстрированы. Кейс допускает пустые совпадения; данные
  специально для проверки не создавались.

Данные проекта не менялись. Наблюдатели удалены (fetch восстановлен),
страницы2/3 закрыты. Сервер тестировщик не останавливал.
Код, БД, кейсы, индексы и конфигурация не менялись; коммитов нет.
