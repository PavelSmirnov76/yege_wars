Именование: `SEC-{n}-{TITLE}.md` — одна проверка на файл.

## Когда

- перед первым push в удалённый репозиторий;
- перед каждым выпуском (`8-deploy/`).

Проверяют конкретный коммит — его хэш в начале файла.

## Что проверить

- **История git целиком**: нет ключей, паролей, строк подключения, ответов
  задач и эталонов; `supabase/seed/local/` и `supabase/.env.local` в истории не
  появлялись.
- **Доступы в базе**: `bash supabase/tests/run_local.sh` → `RLS OK`; ответ
  задачи нельзя получить ни из клиента, ни через API с anon key.
- **Настройки боевой**, от которых зависит доступ: открыта ли регистрация,
  подтверждение почты, роли админа.
- **Ключи**, попавшие в git — в любой коммит истории, — отозваны и заменены.
  Ключ, показанный вне git (в чате, в логе), засвеченным не считается.
- **Зависимости** — известные уязвимости.

Боевую на проверке только читают.

## Находки

Каждая находка — серьёзность и как закрыта. Находку, которая требует изменения
кода или схемы, закрывают заданием конвейера, а не правкой по ходу проверки.
Проверка заморожена: когда находки закрыты, проводят новую проверку `SEC-{n}`
с `supersedes`. В `8-deploy/` идут только с проверкой без открытых находок.
