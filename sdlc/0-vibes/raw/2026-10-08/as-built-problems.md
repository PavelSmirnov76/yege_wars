# Проход «как построено»: задачи и решение

Вход пятого прохода конвейера, 2026-10-08. Описывается построенное на коммите
`d582b2d`, а не задуманное.

## Срез

Каталог задач, страница задачи с файлами данных, запуск программы на Python в
браузере и черновик кода, отправка ответа и его проверка базой, свои попытки,
публикация решения и чужие решения. Дизайн экранов каталога и задачи.

## Границы

Решение владельца 2026-10-08: справка на странице задачи — статьи справочника
по темам задачи и ручные связи, подсказка «Не знаешь, с чего начать?» и ссылки
`[[slug]]` в условии — уходит в срез «справочник». Вкладка «Справка» входит в
раскладку экрана задачи без своих состояний.

Предложено постановщиком и одобрено владельцем в плане прохода:

- прогресс по номерам (`get_user_progress`) и функции администратора по
  попыткам (`admin_list_students`, `admin_student_overview`,
  `admin_task_attempts`, `admin_recent_submissions`) есть только в базе, без
  экранов; они войдут в срезы профиля и админки;
- Content API — функции `admin_*` для задач, файлов и ответов — граница с
  контентом.

## Расхождения с ТЗ

1. На узком экране страница задачи — вкладки «Условие / Код / Решения /
   Справка / Файлы»; по ТЗ — «Условие / Код / Результат». Консоль и поле
   ответа — во вкладке «Код».
2. Python загружается при первом запуске программы, а не при первом открытии
   редактора. Таймаут 60 с считается с нажатия «Запустить» вместе с этой
   загрузкой. Pyodide берётся с jsDelivr, при неудаче — с unpkg.
3. Файлы задачи приходят из базы вместе с задачей (`task_files.content`), а
   не с GitHub Pages. Файл, который лежит в Supabase Storage, клиент показывает
   и отдаёт программе пустым. Поэтому, по `STATE.md`, 60 задач банка с ответами
   не опубликованы: 56 — с вложениями в Storage, 4 ссылаются на условие
   задания 19.
4. Заглушки `turtle` для задания 6 нет.
5. Номер КЕГЭ на карточке каталога не показан: он стоит в заголовке группы.
6. Задача публикуется статусом `published` (`draft`, `review`, `published`),
   а не флагом `is_published`; файлы — отдельная таблица `task_files`, а не
   колонка `tasks.files`. Номер задания необязателен и идёт по спецификации
   2026 (`STATE.md`, «Отступления от ТЗ»).

## Находки

7. Ошибку публикации решения экран не показывает: состояние
   `PublishController` никто не читает. Блок «Задача решена!» скрывается и
   тогда, когда публикация не прошла.
8. Сбой загрузки «Моих попыток» экран не показывает — списка просто нет. При
   сбое загрузки чужих решений вместо списка — индикатор загрузки, сообщения
   об ошибке нет.
9. Пока среда Python загружается — первый запуск на вкладке и первый после
   «Стоп» или таймаута, — состояние «загрузка» держится до конца запуска:
   строка «Загружаю Python…», «Стоп» недоступна, «Запустить» доступна.
   Зациклившуюся программу в таком запуске останавливает только таймаут 60 с.
   Причина в `PyodideRuntime`: сообщение воркера `ready` во время запуска не
   возвращает состояние «выполняется». Повторное «Запустить» в таком запуске
   выводит в консоль «Программа уже выполняется.».
10. Переменные прошлого запуска видны следующему: воркер выполняет код в
    общем пространстве имён Pyodide, пока жив; «Стоп» и таймаут создают воркер
    заново.
11. Черновик хранится по задаче на устройстве (`draft.<slug>`), а не по
    пользователю: на общем компьютере следующий ученик увидит чужой черновик,
    и после выхода он остаётся.
12. Задача без эталонного ответа принимает отправку, но любой ответ получает
    вердикт «неверно».
13. `normalize_answer` срезает с краёв только пробелы: ответ с переводом строки
    на конце для числового формата не совпадает. Клиент срезает края сам до
    отправки (`SubmitAnswerUseCase`).
14. Устаревшие doc-комментарии: `TaskScreen` («Редактор кода, запуск и
    отправка ответа появятся на следующих этапах») и `EditorPanel`
    («Отправка ответа появится на следующем этапе»). Строки l10n
    `editorConsoleTitle` и `editorClearConsole` не используются, у
    `RunController.clear` нет кнопки.
