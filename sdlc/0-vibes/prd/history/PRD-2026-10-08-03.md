# PRD — YEGE Wars

Единственный PRD конвейера; правила — `AGENTS.md` этой папки. Описаны срез
«авторизация и роли» — как построено на коммите `5d49cbe` — и конфигурация
сборки. R17 и адрес после входа в R9 — решения владельца 2026-10-08, ещё не
построены. Остальное построенное войдёт следующими проходами.

## Назначение и границы

YEGE Wars — веб-платформа для подготовки к КЕГЭ по информатике в духе
Codewars: ученик решает задачи экзамена на Python прямо в браузере,
отправляет ответ и видит свой прогресс; преподаватель-администратор следит за
учениками.

Граница: учебная платформа одной группы — без оплаты, почты, комментариев,
лайков, уведомлений и чатов.

## Словарь терминов

| Термин | Значение | Имя в id |
|---|---|---|
| посетитель | человек на сайте без входа | `VISITOR` |
| пользователь | вошедший человек любой роли | `USER` |
| ученик | пользователь с ролью `student` | `STUDENT` |
| администратор | пользователь с ролью `admin` — преподаватель | `ADMIN` |
| логин | имя для входа: 3–20 символов, латинские буквы, цифры, `_` | `USERNAME` |
| учётная запись | запись Supabase Auth: техническая почта `<логин>@ege.local` и пароль | `ACCOUNT` |
| профиль | логин, роль и дата регистрации пользователя | `PROFILE` |
| сессия | состояние «вошёл» — от входа до выхода | `SESSION` |
| роль | `student` или `admin` | `ROLE` |
| регистрация | создание учётной записи и профиля | `REGISTRATION` |
| настройки | общие флаги приложения, например «регистрация открыта» | `SETTINGS` |
| авторизация | регистрация, вход, выход, сессия и доступ по ролям | `AUTH` |
| управление | действия администратора над учётными записями и настройками | `MANAGEMENT` |
| раздел администратора | экран `/admin` и действия `admin_*` в базе | `ADMIN-SECTION` |
| конфигурация сборки | адрес проекта Supabase и публичный ключ, которые задаются при сборке | `BUILD-CONFIG` |
| конфигурация | запуск приложения с конфигурацией сборки | `CONFIG` |

## Цели и не-цели

Цели:

- ученик тренирует задания КЕГЭ и видит свой прогресс;
- администратор видит, что ученики решают и отправляют.

Не-цели: почта и письма, оплата, комментарии, лайки, личные сообщения,
уведомления, чаты.

## Требования

### Регистрация

<a id="r1"></a>**R1.** Посетитель регистрируется по логину и паролю, без почты.

<a id="r2"></a>**R2.** Логин — от 3 до 20 символов: латинские буквы, цифры и подчёркивание; логин уникален.

<a id="r3"></a>**R3.** Пароль — не короче 8 символов.

<a id="r4"></a>**R4.** Новый пользователь получает роль ученика.

<a id="r5"></a>**R5.** Когда регистрация закрыта, зарегистрироваться нельзя, и экран регистрации сообщает об этом.

<a id="r6"></a>**R6.** Открывает и закрывает регистрацию только администратор.

### Вход и сессия

<a id="r7"></a>**R7.** Пользователь входит по логину и паролю; сессия сохраняется при перезагрузке страницы.

<a id="r8"></a>**R8.** Пользователь выходит из учётной записи.

<a id="r9"></a>**R9.** Без входа доступны только экраны входа и регистрации; адрес, с которым пришёл посетитель, открывается после входа.

<a id="r17"></a>**R17.** Если сессия заканчивается, пока страница открыта, — пользователь вышел в этой вкладке или в другой либо сессия закончилась сама, — адрес страницы не запоминается: следующий вход открывает главную.

<a id="r10"></a>**R10.** Профиль показывает логин и роль пользователя.

### Роли

<a id="r11"></a>**R11.** Раздел администратора виден и открывается только администратору: ученик не видит его в меню и не открывает по адресу.

<a id="r12"></a>**R12.** Действия администратора в базе (`admin_*`) выполняет только администратор; остальным — отказ.

<a id="r13"></a>**R13.** Администратор назначает и снимает роль администратора; снять её с себя нельзя.

<a id="r14"></a>**R14.** Администратор задаёт пользователю новый пароль не короче 8 символов.

### Конфигурация

<a id="r15"></a>**R15.** Адрес проекта Supabase и публичный ключ приложение берёт только из параметров сборки; значений по умолчанию в коде нет.

<a id="r16"></a>**R16.** Без адреса или ключа, а также если подключиться к Supabase не удалось, приложение показывает экран «Приложение не сконфигурировано» с причиной.

## Ограничения

- Ключи, пароли и адрес проекта в репозитории не хранятся — только в
  незаливаемых файлах (`supabase/.env.local`).

## Метрики успеха

- Новый пользователь регистрируется по логину без почты и попадает в
  приложение.
- Через API без роли администратора нельзя выполнить ни одно действие
  администратора.
