# PRD — YEGE Wars

Единственный PRD конвейера; правила — `AGENTS.md` этой папки. Описаны срезы
«авторизация и роли» — как построено на коммите `5d49cbe`, — «задачи и

решения владельца, ещё не построенные.

Проход 8 (2026-10-09) — тестовый вход: R48, R49, тоже ещё не построенные.

## Назначение и границы

YEGE Wars — веб-платформа для подготовки к КЕГЭ по информатике в духе
Codewars: ученик решает задачи экзамена на Python прямо в браузере,
отправляет ответ и видит свой прогресс; преподаватель-администратор следит за
учениками.

Граница: учебная платформа одной группы — без оплаты, почты, комментариев,
лайков, уведомлений и чатов.

## Цели и не-цели

Цели:

- ученик тренирует задания КЕГЭ и видит свой прогресс;
- администратор видит, что ученики решают и отправляют.

Не-цели: почта и письма, оплата, комментарии, лайки, личные сообщения,
уведомления, чаты.

## Требования

### Регистрация

<a id="r1"></a>**R1.** Посетитель регистрируется по логину и паролю, без почты.

<a id="r2"></a>**R2.** Логин — от 3 до 20 символов: латинские буквы, цифры и подчёркивание; логин уникален.

<a id="r3"></a>**R3.** Пароль — не короче 8 символов.

<a id="r4"></a>**R4.** Новый пользователь получает роль ученика.

<a id="r5"></a>**R5.** Когда регистрация закрыта, зарегистрироваться нельзя, и экран регистрации сообщает об этом.

<a id="r6"></a>**R6.** Открывает и закрывает регистрацию только администратор.

### Вход и сессия

<a id="r7"></a>**R7.** Пользователь входит по логину и паролю; сессия сохраняется при перезагрузке страницы.

<a id="r8"></a>**R8.** Пользователь выходит из учётной записи.

<a id="r9"></a>**R9.** Без входа доступны только экраны входа и регистрации; адрес, с которым пришёл посетитель, открывается после входа.

<a id="r17"></a>**R17.** Если сессия заканчивается, пока страница открыта, — пользователь вышел в этой вкладке или в другой либо сессия закончилась сама, — адрес страницы не запоминается: следующий вход открывает главную.

<a id="r48"></a>**R48.** На экране входа есть кнопка «Тестовый вход», если при сборке заданы логин и пароль тестовой учётной записи; без них кнопки нет. Кнопка подставляет логин и пароль в поля формы и выполняет вход, как «Войти».

<a id="r10"></a>**R10.** Профиль показывает логин и роль пользователя.

### Роли

<a id="r11"></a>**R11.** Раздел администратора виден и открывается только администратору: ученик не видит его в меню и не открывает по адресу.

<a id="r12"></a>**R12.** Действия администратора в базе (`admin_*`) выполняет только администратор; остальным — отказ.

<a id="r13"></a>**R13.** Администратор назначает и снимает роль администратора; снять её с себя нельзя.

<a id="r14"></a>**R14.** Администратор задаёт пользователю новый пароль не короче 8 символов.

### Конфигурация

<a id="r15"></a>**R15.** Адрес проекта Supabase и публичный ключ приложение берёт только из параметров сборки; значений по умолчанию в коде нет.

<a id="r16"></a>**R16.** Без адреса или ключа, а также если подключиться к Supabase не удалось, приложение показывает экран «Приложение не сконфигурировано» с причиной.

### Сайт

<a id="r41"></a>**R41.** Сайт открывается по адресу `https://pavelsmirnov76.github.io/yege_wars/`.

<a id="r42"></a>**R42.** Новая версия сайта выкладывается только по ручному запуску владельца; выкладывается текущий `main`.

<a id="r49"></a>**R49.** На сайте логин и пароль тестовой учётной записи берутся из секретов GitHub; если они не заданы, сайт выкладывается без кнопки «Тестовый вход».

### Каталог задач

<a id="r18"></a>**R18.** Пользователь видит каталог опубликованных задач, сгруппированный по номеру КЕГЭ по возрастанию; задачи без номера — отдельной группой в конце.

<a id="r19"></a>**R19.** Каталог отбирает задачи по номеру КЕГЭ, сложности, состоянию решения и части названия.

<a id="r20"></a>**R20.** Карточка задачи показывает название, сложность, состояние решения пользователя и долю решивших; попытки администраторов в долю не входят.

### Страница задачи

<a id="r21"></a>**R21.** Страница задачи показывает номер КЕГЭ, сложность, условие, источник и файлы задачи.

<a id="r22"></a>**R22.** Файл задачи можно просмотреть по первым строкам, скопировать и скачать.

<a id="r23"></a>**R23.** Неопубликованной задачи нет ни в каталоге, ни на странице задачи.

### Запуск программы

<a id="r24"></a>**R24.** Пользователь запускает программу на Python в браузере: программа открывает файлы задачи по их именам и читает ввод из поля «Ввод (stdin)», а вывод и ошибки показываются в консоли.

<a id="r25"></a>**R25.** Запуск останавливается кнопкой «Стоп» или сам через 60 секунд; интерфейс при этом не зависает.

<a id="r43"></a>**R43.** Пока запуск не закончился — в том числе пока загружается Python, — «Стоп» доступна, а «Запустить» нет.

<a id="r26"></a>**R26.** **Устарело 2026-10-09, заменено [R44](../PRD.md#r44).** Код задачи сохраняется черновиком на устройстве и подставляется при следующем открытии задачи.

<a id="r44"></a>**R44.** Черновик хранится в базе — отдельно для каждого пользователя и задачи — и подставляется при открытии задачи на любом устройстве.

<a id="r45"></a>**R45.** Свой черновик видит и меняет только его автор.

### Ответ и попытки

<a id="r27"></a>**R27.** Пользователь отправляет ответ; база сравнивает его с эталонным ответом по формату задачи и записывает попытку с вердиктом.

<a id="r28"></a>**R28.** Пользователь отправляет не больше 10 ответов в минуту.

<a id="r29"></a>**R29.** Эталонный ответ, эталонное решение и разбор задачи недоступны клиенту ни в интерфейсе, ни через API.

<a id="r30"></a>**R30.** Попытку нельзя записать или изменить в обход проверки ответа.

<a id="r31"></a>**R31.** Кнопка «Взять из вывода» подставляет в поле ответа ответ из вывода программы по формату задачи.

<a id="r32"></a>**R32.** Пользователь видит свои попытки по задаче — ответ, вердикт и время, сначала свежие.

### Решения

<a id="r33"></a>**R33.** Пользователь публикует свою верную попытку как решение и снимает её с публикации; неверную или чужую попытку опубликовать нельзя.

<a id="r47"></a>**R47.** Если публикация решения или её снятие не удались, пользователь видит сообщение об ошибке и может повторить действие.

<a id="r34"></a>**R34.** Чужие опубликованные решения задачи видит только тот, кто сам решил её верно: логин автора, дату и код, сначала свежие.

### Справочник

<a id="r35"></a>**R35.** Справочник показывает опубликованные статьи: название, описание, уровень, время чтения, номера КЕГЭ и теги; статьи идут по уровню, внутри уровня — по названию.

<a id="r36"></a>**R36.** Статьи справочника отбираются по уровню, номеру КЕГЭ, тегу и части названия или описания.

<a id="r37"></a>**R37.** Страница статьи показывает название, уровень, время чтения, номера КЕГЭ, теги и текст статьи с примерами кода на Python.

<a id="r38"></a>**R38.** Ученику неопубликованная статья не видна ни в справочнике, ни на странице статьи, ни в справке к задаче, ни в ссылках на статьи.

<a id="r39"></a>**R39.** Справка к задаче — статьи по темам задачи и по ручным связям; главные идут первыми, каждая статья — один раз.

<a id="r40"></a>**R40.** Ссылка на статью в условии задачи или в тексте статьи открывает статью; ссылка на неизвестную статью показывается обычным текстом.

### Сбои загрузки

<a id="r46"></a>**R46.** Если загрузка экрана или списка не удалась, сразу показываются сообщение об ошибке и кнопка «Повторить»; автоматических повторов нет.

## Ограничения

- Ключи, пароли и адрес проекта в репозитории не хранятся — только в
  незаливаемых файлах (`supabase/.env.local`).
- Копии базы по расписанию нет: копию снимают вручную по запросу владельца.
- Базу, уснувшую на бесплатном тарифе Supabase, владелец восстанавливает
  вручную.

## Метрики успеха

- Новый пользователь регистрируется по логину без почты и попадает в
  приложение.
- Через API без роли администратора нельзя выполнить ни одно действие
  администратора.
- В задаче 24 программа с `open('24.txt')` читает файл задачи, выводит
  результат, ответ отправляется и засчитывается.
- Бесконечный цикл останавливается кнопкой «Стоп» или по таймауту; интерфейс
  не зависает.
- Ответ задачи нельзя узнать ни из интерфейса, ни через API.
- Чужие решения недоступны до своего верного ответа.
- Сайт работает на телефоне шириной 360 px и на десктопе.

## План работ и вехи

**Выпуск для учеников — 2026-10-10.** Входят [R41](../PRD.md#r41)–[R49](../PRD.md#r49). Перед
публикацией владелец заводит учётные записи учеников и тестовую учётную запись
и закрывает регистрацию
([R5](../PRD.md#r5), [R6](../PRD.md#r6)); после выкладки проверяет сайт на своём телефоне.

После выпуска: раздел администратора — списки учеников и их попыток (попытки
с кодом и черновики уже хранятся в базе); профиль с прогрессом; задачи с
файлами и картинками из Storage.
