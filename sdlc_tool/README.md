# sdlc_tool — скрипт конвейера

Ведёт id и ссылки конвейера `sdlc/`: проверяет дерево, выдаёт id, собирает
производные файлы, хоронит артефакты, снимает PRD и прогоняет проверки
проекта. Закон, которому он служит, — `sdlc/AGENTS.md`; здесь — как скрипт его
исполняет. Форматы, которые пишут люди и агенты, живут в `AGENTS.md` стадий,
здесь на них ссылки. Форматы, которые пишет сам скрипт, описаны здесь.

Python 3.9, только стандартная библиотека. Запуск из корня репозитория:

```bash
python3 -m sdlc_tool <команда> [параметры]
python3 -m unittest discover -s sdlc_tool/tests -t .     # тесты скрипта
```

## Команды

| Команда | Что делает | Код возврата |
|---|---|---|
| `check [--base REF]` | все проверки; база по умолчанию `HEAD`, `--base none` — без сравнения с базой | 0 — ошибок нет, 1 — есть ошибки |
| `views` | пересобирает `INDEX.md` и `sdlc/6-eval/DASHBOARD.md` | 0 |
| `next ТИП [ВЛАДЕЛЕЦ]` | печатает следующий id | 0; 2 — неверный вызов |
| `entomb ID --by ID\|none [--why ТЕКСТ] [--date ГГГГ-ММ-ДД]` | хоронит артефакт или отмечает устаревшим требование, затем `views` | 0; 1 — отказ |
| `snapshot-prd --why ТЕКСТ --input ПУТЬ [--date ГГГГ-ММ-ДД]` | снимает PRD в `history/`, затем `views` | 0; 1 — отказ |
| `run [--allow-dirty] [--skip ИМЯ,…]` | прогоняет проверки проекта, пишет прогон в `sdlc/6-eval/auto/`, затем `views` | 0 — всё `PASS`; 1 — есть `FAIL`; 3 — `FAIL` нет, но есть `BLOCKED` |

Общий параметр `--root ПУТЬ` — корень репозитория, по умолчанию текущая папка.
Дата по умолчанию — сегодняшняя, по локальному времени.

`next`: `next UC` → `UC-4`; `next R` → `R12`; `next RESULT TASK-7` →
`RESULT-TASK-7-02`; `next ACC RESULT-TASK-7-02` → `ACC-TASK-7-02` (отказ, если
такой сдачи нет или у неё уже есть приёмка). Номер — на единицу больше
наибольшего в рабочем дереве, считая похороненные; у требований — в PRD.

Сообщения — по-русски, по одному в строке:

```
ОШИБКА sdlc/2-specs/actors/ACTOR-3-X-IN-AUTH.md:12: текст ссылки ACTOR-4, а ведёт она на ACTOR-3
ПРЕДУПРЕЖДЕНИЕ sdlc/0-vibes/prd/PRD.md: 312 строк — пора разбивать
Итог: 1 ошибка, 1 предупреждение
```

Путь — от корня репозитория, номер строки — где он известен. Порядок
сообщений — по пути, затем по строке, затем по тексту.

## Модель дерева

Все пути ниже — от `sdlc/`, кроме кода продукта.

### Артефакты-файлы

| Тип | Папка | Имя файла |
|---|---|---|
| `BT` | `1-business-tasks/observation/errors/` (`ERROR`), `…/warnings/` (`WARNING`), `…/infos/` (`INFO`), `1-business-tasks/planning/` (`PLANNING`) | `BT-{n}-{TYPE}-{TITLE}.md` |
| `MOD` | `2-specs/modules/` | `MOD-{n}-{WORD}.md` |
| `ACTOR` · `ENT` · `EVT` | `2-specs/actors/` · `2-specs/entities/` · `2-specs/events/` | `{ТИП}-{n}-{NAME}-IN-{WORD}.md` |
| `UC` | `2-specs/use-cases/` | `UC-{n}-ACTOR-{a}-EVT-{e}-ENT-{s}-{NAME}-IN-{WORD}.md` |
| `TOKEN` | `3-design/design-system/` | `TOKEN-{n}-{WORD}.md` |
| `COMP` | `3-design/design-system/` | `COMP-{n}-{NAME}.md` |
| `FIG` | `3-design/` | `FIG-{n}-{NAME}.md` |
| `TASK` | `4-tasks/` | `TASK-{n}-{NAME}.md` |
| `RESULT` | `5-results/` | `RESULT-TASK-{n}-{NN}.md` или `RESULT-TASK-{n}-{NN}-{NAME}.md` |
| `ACC` | `6-eval/acceptance/` | `ACC-TASK-{n}-{NN}.md` или `ACC-TASK-{n}-{NN}-{NAME}.md` |
| `TC` | `6-eval/manual/` | `TC-{n}-{NAME}.md` |
| `SEC` | `7-security-check/` | `SEC-{n}-{NAME}.md` |
| `REL` | `8-deploy/` | `REL-{n}-{NAME}.md` |

- `{n}` — целое без ведущих нулей, от 1. `{NN}` — минимум две цифры: `01`…`99`,
  `100`…
- `{WORD}` — одно слово `[A-Z0-9]+`. `{NAME}`, `{TITLE}` —
  `[A-Z0-9]+(-[A-Z0-9]+)*`. Слова-типы (`BT MOD ACTOR ENT EVT UC TOKEN COMP FIG
  TASK RESULT ACC TC SEC REL`) отдельным словом в `{WORD}`, `{NAME}` и
  `{TITLE}` запрещены.
- В `-IN-{WORD}` имя делится по последнему `-IN-`. `{WORD}` — имя существующего
  модуля: есть файл `MOD-*-{WORD}.md`.
- Id артефакта — тип и номер: `BT-3`, `UC-4`, `RESULT-TASK-7-02`,
  `ACC-TASK-7-02`. Имя файла начинается с id.
- Похороненный артефакт лежит в `obsolete/` внутри своей папки, имя то же.

В папке артефактов (и в её `obsolete/`) других `.md`, кроме `README.md`,
`AGENTS.md`, `CLAUDE.md` и `INDEX.md`, быть не может.

### Папки

- **Папки структуры** — `sdlc/` и все папки под ним, кроме папок содержимого. В
  каждой есть `README.md`, `AGENTS.md` и `CLAUDE.md`.
- **Папки содержимого** — `obsolete/` на любом уровне, папки дат в
  `0-vibes/raw/`, всё под `6-eval/auto/`, папки дат в `6-eval/manual/` и всё под
  ними, `0-vibes/prd/PRD/`, если PRD разбит. В них нет и не должно быть
  `README.md`, `AGENTS.md`, `CLAUDE.md`.

### Требования

PRD — `0-vibes/prd/PRD.md`, а если он разбит — все `.md` в `0-vibes/prd/PRD/`.

- Требование начинается строкой
  `<a id="r{n}"></a>**R{n}.** …` — номер в якоре и в тексте один.
- Текст требования — от этой строки до пустой строки, заголовка или следующего
  требования.
- Отметка устаревания — сразу после `**R{n}.**`, ровно в виде из
  `0-vibes/prd/AGENTS.md`: ` **Устарело ГГГГ-ММ-ДД, заменено [R{k}](#r{k}).**`
  или ` **Устарело ГГГГ-ММ-ДД, заменено ничем.**`. Требование без отметки живое.

### Пути UC

В файле UC (формат — `2-specs/use-cases/AGENTS.md`):

- путь — заголовок `### <a id="uc-{n}-p-{nn}"></a>UC-{n}-P-{nn} — <имя>`, где
  `{n}` — номер этого UC;
- в разделе пути, до следующего заголовка `##` или `###`, — ровно одна строка
  `**Исход:** UC-{n}-O-{nn} — <имя>` с тем же `{nn}`.

### Ссылки

- Ссылка — `[текст](цель)` в Markdown, не картинка, вне блоков кода (```` ``` ````)
  и вне кода в строке (`` ` ``).
- Проверяются все `.md` под `sdlc/`, кроме `0-vibes/raw/`, `6-eval/auto/` и папок
  дат в `6-eval/manual/`.
- Цель со схемой (`https:`, `mailto:`) не проверяется. Остальные разрешаются от
  папки файла, `%XX` раскодируется, `#якорь` без пути — тот же файл.
- **Ссылка на артефакт** — цель разрешается в файл артефакта, живой или
  похороненный. Видимый текст: без якоря — id артефакта; в файл UC с якорем
  `#uc-{n}-p-{nn}` — `UC-{n}-P-{nn}`; с другим якорем — id артефакта. Якорь
  должен быть в файле: `<a id="…"></a>`.
- **Ссылка на требование** — цель — PRD (или его часть) с якорем `#r{n}`:
  текст `R{n}`, якорь есть.
- Текст, который целиком похож на id (`R7`, `UC-3`, `UC-3-P-02`,
  `RESULT-TASK-7-02`…), — только у ссылки на этот самый артефакт.
- Любая относительная цель должна существовать — файл или папка.

### Метки в коде

- Где: `lib/`, `test/`, `web/`, `supabase/` от корня репозитория; файлы `.dart`,
  `.sql`, `.py`, `.js`, `.html`; без `*.g.dart` и `lib/l10n/gen/`.
- Метка — голый id: `UC-{n}`, `UC-{n}-P-{nn}`, `TOKEN-{n}`, `COMP-{n}`; соседний
  символ слева и справа — не буква, не цифра и не дефис.
- Файлы темы — `lib/app/theme/*.dart`.

### `supersedes` и шапки

- Заменяющий артефакт — строка `supersedes: [ID](путь)` (закон, «Устаревание»).
- Шапка похороненного артефакта (пишет `entomb`), сверху файла:

  ```markdown
  > **Похоронен:** 2026-11-02
  > **Почему:** <текст>
  > **Заменён:** [UC-9](../UC-9-ACTOR-1-EVT-2-ENT-3-SIGNED-IN-IN-AUTH.md)

  <исходный текст без изменений>
  ```

  Если замены нет — `> **Заменён:** ничем`.
- Шапка снимка PRD (пишет `snapshot-prd`), файл
  `0-vibes/prd/history/PRD-ГГГГ-ММ-ДД.md`, второй за день — `…-02.md`:

  ```markdown
  > **Сменён:** 2026-11-02
  > **Почему:** <текст>
  > **Вход:** [0-vibes/raw/2026-11-02/](../../raw/2026-11-02/)

  <текст PRD, пути ссылок перебазированы>
  ```

### Строки, которые читает скрипт

- Вердикт приёмки — `**Вердикт:** принято` или `**Вердикт:** возврат`
  (`6-eval/acceptance/AGENTS.md`).
- Вердикт прогона ручного кейса — `**Вердикт:** PASS`, `FAIL` или `BLOCKED` в
  `transcript.md` (`6-eval/manual/AGENTS.md`).
- Название артефакта — первый заголовок `# …` без id в начале и без
  разделителя после него (`:`, `—`, `–`, `-`); нет заголовка — часть имени
  файла после id.

## База: что новое

`check --base REF` сравнивает рабочее дерево (с неотслеживаемыми файлами) с
коммитом `REF`. Без базы (`--base none`) проверки этого раздела не делаются.

- **Новый артефакт** — его id нет в базе.
- **Заморозка.** Артефакт, который есть в базе, совпадает с базовым текстом,
  если у обоих убрать шапку похороненного и пути в ссылках (`](…)` → `]()`).
  Иначе — ошибка. Перенос разрешён только из живой папки в её `obsolete/`.
  Удалять артефакт нельзя. Снимки PRD в `history/` заморожены так же.
- **Требования.** Каждое требование базы осталось в PRD, и его текст — без
  отметки устаревания и без путей в ссылках — тот же.
- **Порядок id.** Номер нового id больше наибольшего номера этого типа в базе;
  у сдач и приёмок — больше наибольшего `{NN}` этого задания.
- **Новые ссылки** — все ссылки новых артефактов и ссылки в добавленных строках
  PRD — не ведут на похороненный артефакт и на устаревшее требование.
- **Новые метки** — метки в добавленных строках кода (`git diff` с базой плюс
  неотслеживаемые файлы) — не ведут на похороненный id.

## Проверки `check`

Ошибки:

1. Файл в папке артефактов не по грамматике имени; артефакт не в своей папке
   (у бизнес-задачи — `{TYPE}` не тот, что у папки); в папке структуры нет
   `README.md`, `AGENTS.md` или `CLAUDE.md`; в папке содержимого есть они.
2. Один id у двух файлов.
3. `-IN-{WORD}` не ведёт на модуль; в имени UC — несуществующие `ACTOR`, `EVT`,
   `ENT`; у сдачи или приёмки нет её задания; у приёмки нет сдачи с тем же
   `{NN}`.
4. Требования: номер в якоре и тексте разный; номер повторён; отметка
   устаревания не по формату; заменяющее требование не существует.
5. Пути UC: заголовок или якорь не по формату; номер UC не тот; у пути нет
   исхода или их два; номер исхода не равен номеру пути; путь повторён.
6. Ссылки: цель не существует; текст ссылки на артефакт — не его id; текст,
   похожий на id, ведёт не на этот артефакт; нет якоря.
7. Метка в коде ведёт на несуществующий UC, путь UC, токен или компонент.
8. У приёмки нет строки вердикта или она не по формату.
9. `supersedes` ведёт на несуществующий или не похороненный артефакт; шапка
   похороненного («Заменён») и `supersedes` заменяющего не сходятся.
10. Импорт в `CLAUDE.md` (строка `@путь`) не разрешается.
11. В экране `FIG` — значение вместо токена: цвет `#RRGGBB`, `#RGB`,
    `#RRGGBBAA` или размер `12px`, `12dp`, `12pt`, `12sp` (вне кода и целей
    ссылок).
12. Производный файл устарел, отсутствует или лишний.
13. Ошибки раздела «База: что новое».

Предупреждения — код возврата не меняют:

- PRD длиннее 300 строк; `AGENTS.md` или `README.md` — 300 строк и длиннее;
- живой артефакт ссылается на похороненный артефакт или устаревшее требование
  — к пересмотру;
- старая метка в коде ведёт на похороненный id — к пересмотру.

## Производные файлы

`views` пишет их, `check` сравнивает с тем, что собрал бы сам. Порядок строк —
по номеру id (у сдач и приёмок — по заданию, затем по `{NN}`). Дат сборки нет.
Пути в ссылках — от папки производного файла. Каждый начинается строкой:

```markdown
<!-- Производный файл: собирает `python3 -m sdlc_tool views`, руками не править. -->
```

### `INDEX.md`

Есть в каждой папке артефактов, где лежит хотя бы один артефакт — живой или
похороненный; где нет ни одного — `INDEX.md` нет.

```markdown
# Индекс: `2-specs/use-cases/`

| Id | Название | Ссылается на | …колонки папки… |
|---|---|---|---|
| [UC-3](UC-3-…md) | Вход по паролю | [R1](../../0-vibes/prd/PRD.md#r1), [BT-2](…) | … |

## К пересмотру

| Id | Ссылается на похороненное |
|---|---|

## Похоронены

| Id | Название | Заменён |
|---|---|---|
```

- «Ссылается на» — id из ссылок файла на артефакты и требования, без самого
  артефакта, в порядке первого появления, ссылками.
- Разделы «К пересмотру» и «Похоронены» — только если в них есть строки.

Колонки папок:

| Папка | Колонки |
|---|---|
| `1-business-tasks/planning/` | «Закрыта»: `да`; `нет — нет UC`; `нет — не проверено: UC-3-P-02, …`; `нет — FAIL: …` |
| `2-specs/use-cases/` | «Пути» — число; «Проверено» — `k из m`; «Где реализован» — файлы с меткой `UC-{n}` |
| `3-design/design-system/` | «Где реализован» — файлы с меткой; после таблиц — раздел «Файлы темы без метки» |
| `4-tasks/` | «Пути UC» — ссылки из основания; «Сдачи»; «Приёмки» — со вердиктом; «Закрыто» — `да`, если последняя приёмка «принято» |
| `5-results/` | «Задание»; «Приёмка» — ссылка и вердикт или `нет` |
| `6-eval/acceptance/` | «Сдача»; «Вердикт» |
| `6-eval/manual/` | «Путь UC»; «Последний прогон» — дата и вердикт |

Закрытость бизнес-задачи планирования: у всех путей всех живых UC, которые на
неё ссылаются, вердикт сводки `PASS`. UC нет — открыта.

### `6-eval/DASHBOARD.md`

Есть, когда есть PRD.

```markdown
# Сводка проверки

Последний машинный прогон: [2026-10-12-1a2b3c4](auto/2026-10-12-1a2b3c4/summary.md)

| Требование | UC | Путь | Вердикт | Источник |
|---|---|---|---|---|
| [R1](../0-vibes/prd/PRD.md#r1) | [UC-3](…) | [UC-3-P-01](…#uc-3-p-01) | PASS | auto 2026-10-12-1a2b3c4 |
| [R2](…) | — | — | НЕ ПРОВЕРЕНО: нет UC | — |

Итого путей: PASS 1, FAIL 0, BLOCKED 0, НЕ ПРОВЕРЕНО 0.

## Устаревшие требования

| Требование | Заменено |
|---|---|
```

- Строки — по живым требованиям, внутри — по живым UC, которые на требование
  ссылаются, внутри — по путям. Требование без UC — одна строка «нет UC».
- Вердикт пути из машинного прогона — только из последнего полного прогона,
  без проверок, пропущенных через `--skip` (по `started_at` в `summary.json`,
  затем по имени папки). Частичный прогон остаётся доказательством в своей
  папке, но сводку не задаёт. В нём: `FAIL`, если упал хоть один тест с меткой
  пути; иначе `BLOCKED`, если хоть один заблокирован; иначе `PASS`, если тесты
  с меткой есть. Нет тестов с меткой — машинного вердикта нет.
- Вердикт из ручной проверки — последний раунд по дате у каждого живого кейса
  `TC` со ссылкой на этот путь.
- Из машинного и ручного берётся более поздний по дате; при равной дате — худший
  (`FAIL` хуже `BLOCKED`, `BLOCKED` хуже `PASS`). Нет ни того, ни другого —
  `НЕ ПРОВЕРЕНО`.
- Раздел «Устаревшие требования» — только если они есть.

## Прогон `run`

Проверяет закоммиченное состояние: изменённые отслеживаемые файлы или
неотслеживаемые файлы в `lib/`, `test/`, `web/`, `supabase/` — отказ, если не
передан `--allow-dirty` (тогда `"dirty": true` в итоге).

Проверки — по порядку; `--skip` пропускает по имени:

| Имя | Команда | Вердикт |
|---|---|---|
| `pub_get` | `flutter pub get` | подготовка |
| `gen_l10n` | `flutter gen-l10n` | подготовка |
| `build_runner` | `dart run build_runner build --delete-conflicting-outputs` | подготовка |
| `analyze` | `flutter analyze --fatal-infos --fatal-warnings` | по коду возврата |
| `custom_lint` | `dart run custom_lint` | по коду возврата |
| `format` | `dart format --output=none --set-exit-if-changed` по `lib/` и `test/` без `*.g.dart` и `lib/l10n/gen/` | по коду возврата |
| `flutter_test` | `flutter test --reporter json` | по тестам |
| `rls` | `bash supabase/tests/run_local.sh` | `PASS` — код 0 и в выводе `RLS OK` |
| `tools_tests` | `python3 -m unittest discover -s tools/tests -t .` | по коду возврата |
| `sdlc_tool_tests` | `python3 -m unittest discover -s sdlc_tool/tests -t .` | по коду возврата |

- Flutter и Dart: переменные `SDLC_FLUTTER` и `SDLC_DART`, иначе
  `~/fvm/versions/<версия из .fvmrc>/bin/`, иначе `flutter` и `dart` из `PATH`.
  Нет — проверки Flutter `BLOCKED` с причиной.
- Упала подготовка — проверки Flutter `BLOCKED` с причиной.
- `rls` без PostgreSQL (`pg_ctl` в `PATH` или в
  `/opt/homebrew/opt/postgresql@17/bin`) — `BLOCKED`.
- Тесты Flutter — из событий `--reporter json`: `testStart` (имя, набор),
  `testDone` (`success` — `PASS`, `failure` и `error` — `FAIL`), скрытые и
  пропущенные не считаются. Метка пути — из полного имени теста.
- Метки SQL — комментарии `-- UC-{n}-P-{nn}` в `supabase/tests/*.sql`: каждая
  получает вердикт `rls`, отдельных проверок `run_local.sh` не различает.
- Метки в тестах Python — пока не разбираются: продуктовых тестов на Python
  нет.

Папка прогона — `6-eval/auto/<ГГГГ-ММ-ДД>-<короткий хэш HEAD>/`, второй прогон
того же коммита в тот же день — `…-02`. В ней:

- `summary.json` — `commit`, `commit_short`, `date`, `started_at`,
  `finished_at` (ISO), `dirty`, `checks` (`name`, `command`, `verdict`,
  `exit_code`, `reason`, `output_tail`), `tests` (`file`, `name`, `label`,
  `verdict`), `paths` (метка пути → вердикт), `totals` (`pass`, `fail`,
  `blocked`);
- `summary.md` — коммит и дата, таблица проверок, таблица «путь UC | тест |
  вердикт», хвосты вывода упавших проверок.

Хвост вывода — до 60 последних строк; строки подключения, ключи `sb_secret_…`
и JWT в нём заменяются на `***`.
