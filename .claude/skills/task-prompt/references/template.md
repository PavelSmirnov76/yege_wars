# Шаблон промта

Скелет `docs/PROMPT_<ИМЯ>.md`. Разделы в угловых скобках заполняются под
задачу. Блоки без скобок — готовый текст: переносить как есть, при
необходимости подставляя имена.

Части, которые задаче не нужны, выбрасываются целиком. Например, «Боевая
база» в чисто клиентской задаче. Тогда стоп один — перед коммитом.

````markdown
# Задание: <что сделать, одной строкой>

## Зачем

<Проблема и почему её решаем сейчас: факты с числами. Чем закончится
работа. Что вне задания и будет отдельным заданием.>

Прочитать перед работой: <`CLAUDE.md`, нужные разделы `docs/STATE.md`,
отчёты прошлых заданий, файлы кода и миграции, которые задача затронет>.

## Решения, принятые при постановке

| Когда | Вопрос | Ответ пользователя |
|---|---|---|
| <ГГГГ-ММ-ДД> | <вопрос> | <ответ> |

## Исходное состояние (проверено <ГГГГ-ММ-ДД>)

| Что | Состояние |
|---|---|
| <объект> | <проверенный факт: путь, число, поведение кода, ловушка> |
| Проверки | <базовый прогон: сколько тестов, замечаний анализатора> |
| `yege_wars`, ветка `main` | не закоммичены `CLAUDE.md` (указатель на это задание) и этот файл. Их не менять, в коммит они идут как есть. `reference/` в корне — вне задания: не трогать, не коммитить |

## Часть 1. Локально

### 1.1. <шаг>

<Что сделать, контракт (сигнатура, коды ошибок, что меняется и что
нет), тесты, которые доказывают результат.>

### Проверки части 1

```bash
<команды из CLAUDE.md для затронутых слоёв и ожидаемый итог каждой>
```

дословно. Спросить вопросом с вариантами: <применять ли к боевой базе /
коммитить ли>. Без ответа «да» дальше не идти.

<Стоп-условия, если есть: при чём остановиться и доложить, ничего

## Часть 2. Боевая база (только после «да»)

   файл не пустой и в конце есть `dump complete`.
2. **Снимок «до»** (сессия только на чтение): <что снять>.
3. **Миграция** — `psql "$SEED_DATABASE_URL" -v ON_ERROR_STOP=1 -f …`.
4. **Пилот на одном объекте**, проверка, что он изменился ровно как
   задумано.
5. **Остальное.**
6. **Снимок «после»**: <что должно сойтись>.

и доложить. Откат — из дампа шага 1.

### СТОП 2

Отчёт и коротко в чат: выводы «после». Спросить про коммит.

## Часть 3. Git (только после подтверждения)

1. **Коммит работы.** Сообщение на русском, в стиле истории. В него идут
   <перечень>, отчёт, этот файл и `CLAUDE.md`. Файлы добавлять по именам:
   `git add -A` и `git add .` не использовать. Перед коммитом проверить
   `git status`: в индексе нет `reference/`, `supabase/seed/local/`,
   `supabase/.env.local`, `*.g.dart`, `lib/l10n/gen/`.
2. **Коммит — в отчёт.** Дописать в отчёт раздел «Коммит»: хэш, заголовок
   и вывод `git show --stat --format='%H%n%s' <хэш>` дословно. Если
   коммитов несколько — все по порядку.
3. **Отдельным коммитом — только отчёт**, сообщение
   «Отчёт <задание>: коммит <короткий хэш>». Отдельного подтверждения
   этот коммит не требует: он входит в уже подтверждённый.

Ничего не пушить: remote нет.

## Отчёт

`docs/<ИМЯ>_REPORT.md`. Заводится в начале работы и дополняется на каждом
СТОПе и после каждого шага на боевой, а не пишется в конце: так он
переживёт обрыв сессии. <Если есть секреты: ответов и эталонов в нём
нет.>

1. **Состояние**: что сделано, на каком шаге, дата.
2. **Журнал решений**: каждый вопрос пользователю и его ответ — дата,
   вопрос, варианты, выбранный вариант. Запись делается сразу, как пришёл
   ответ. Размышления не записываются, только вопросы и решения.
3. **Изменённые файлы**.
4. **Проверки**: выводы дословно — локальные и на боевой («до», пилот,
   «после»).
5. **Отступления от задания** и **найдено вне задания**: всё, что не
   исправлялось, — сюда, а не только в чат.
6. **Коммит**: хэш, заголовок, `git show --stat` (см. «Git»).
````

## Готовые проверки для «Проверок» и «Приёмки»

- **Dart**:
  ```bash
  FL=~/fvm/versions/3.41.0/bin/flutter; DA=~/fvm/versions/3.41.0/bin/dart
  $FL gen-l10n && $DA run build_runner build --delete-conflicting-outputs
  $FL analyze --fatal-infos --fatal-warnings      # 0 замечаний
  $DA run custom_lint                             # 0 замечаний
  $FL test                                        # все проходят
  find lib test -name '*.dart' -not -name '*.g.dart' -not -path 'lib/l10n/gen/*' \
    -print0 | xargs -0 $DA format --output=none --set-exit-if-changed
  ```
- **БД**: `bash supabase/tests/run_local.sh` → `RLS OK`. Новый объект
  в `public` дописывается в ожидаемую матрицу прав, раздел (п)
  `rls_tests.sql`, иначе тест упадёт. «Тест не холостой» — прогон без
  новой миграции падает.
- **Банк ФИПИ**: `bash supabase/tests/run_import_check.sh` → `IMPORT OK`.
  На боевой — `import_checks.sql` с параметрами, которые вычисляет этот
  скрипт.
- **Python**: `python3 -m unittest discover -s tools/tests -t .` → `OK`.
