# Шаблон задания

Скелет `sdlc/4-tasks/TASK-{n}-{TITLE}.md`. Разделы в угловых скобках
заполняются под задание. Блоки без скобок — готовый текст: переносить как
есть, при необходимости подставляя имена.

Части, которые заданию не нужны, выбрасываются целиком. Например, «Боевая база»
в задании без миграций — тогда стоп один, перед коммитом. «СТОП 0» — только
когда устройство под контракт выбирает исполнитель.

## СТОП 0. План решений до кода

Контракт — RPC, коды ошибок, права, состав экрана — задан спеками и дизайном
из «Основания». Если для работы нужен контракт, которого там нет или который им
противоречит, — стоп и доклад, а не решение по ходу.

До первой строки кода, включая тесты, прислать владельцу план — нумерованный
список решений об устройстве: <что решить: таблицы и миграции под контракт,
где живёт логика, библиотеки, что меняется в существующем коде>.

- Один пункт — одно решение: что решается, варианты, рекомендация и
  последствия выбора. Ни один пункт не «на усмотрение».
- Очевидное идёт в план наравне со спорным: молча проходят как раз те
  решения, которые потом переделывают.
- Сначала назвать штатный механизм платформы — фреймворка, библиотеки, самого
  проекта, — потом своё устройство. Своё вместо штатного — тоже решение.
- Каждый пункт принимается отдельно, и молчание — не согласие. Работа не
  начинается, пока по каждому номеру нет ответа; неотвеченный пункт держит
  только свою часть работы. Фразы «остальное считаю принятым» и «если
  возражений нет, делаю так» запрещены.

Ответы — в сдачу, раздел «Обсуждение», сразу, как пришли.

## Часть 2. Боевая база (только после «да»)

На боевой задание меняет только схему — миграциями. Данные через Content API —
работа с контентом, в задание она не входит.

Доступы: `set -a; . supabase/.env.local; set +a`. Значения переменных никуда
не выводить.

0. **Очередь на боевую.** На боевую владелец пускает одно задание за раз —
   его «да» на СТОПе 1 и есть очередь. Обновить ветку от `main`
   (`git merge main`). Миграция задания должна идти позже последней миграции
   в `main` — иначе переименовать файл (он ещё не применён) — и прогнать
   проверки заново.
1. **Дамп** `~/backups/yege_wars/before-<имя>-<ГГГГММДД-ЧЧММСС>.sql`
   (`pg_dump --schema=public --no-owner`, с правами). Убедиться, что файл не
   пустой и в конце есть `dump complete`.
2. **Снимок «до»** (сессия только на чтение): <что снять>.
3. **Миграция** — `psql "$SEED_DATABASE_URL" -v ON_ERROR_STOP=1 -f …`.
4. **Проверка на одном объекте**, что изменилось ровно задуманное.
5. **Снимок «после»**: <что должно сойтись>.

  На боевой — `import_checks.sql` с параметрами, которые вычисляет этот
