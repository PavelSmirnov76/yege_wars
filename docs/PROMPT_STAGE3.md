Ты — senior Flutter/Dart разработчик. Продолжаешь готовый проект, этапы 1–2

3. `docs/STATE.md` — что уже сделано, контракты кода и БД, окружение.

## Задача этапа

Заменить временный стаб авторизации на реальную работу с Supabase Auth:
регистрация и вход по логину/паролю, профиль из таблицы `profiles`, guard'ы
по статусу и роли. БД полностью готова (миграции этапа 2) — менять её не нужно.

## Требования

1. **Подключение Supabase.** Добавить пакет `supabase_flutter`
   (`$DA pub add supabase_flutter`, пути к бинарникам — в CLAUDE.md).
   Инициализация до `runApp` через `Env.supabaseUrl` / `Env.supabaseAnonKey`.
   Если `Env.isConfigured == false` — приложение показывает понятный
   экран-заглушку «Приложение не сконфигурировано», а не падает.
   Инициализацию отделить от `runApp` (bootstrap-функция), чтобы тесты могли
   собрать приложение без Supabase через override провайдеров.

2. **Фича auth по Clean Architecture** (папки уже существуют):
   - **domain**: entity `UserProfile` (id, username, role: `enum UserRole
     {student, admin}`); интерфейс `AuthRepository` (signUp, signIn, signOut,
     watchAuthState/currentProfile, isRegistrationOpen); use case'ы. Все методы
     возвращают `FutureResult<…>` (см. `lib/core/error/`), никаких исключений
     наружу. Domain не импортирует Flutter и Supabase.
   - **data**: datasource поверх `SupabaseClient` + реализация репозитория.
     Логин → техпочта `<username>@ege.local`. Регистрация: `signUp` с
     `data: {'username': username}` — профиль создаёт триггер БД
     `handle_new_user`. Профиль читать из `profiles` по `auth.uid`.
     `is_registration_open` — RPC (доступна и до входа).
   - **Маппинг ошибок** в `AuthFailure` с русским текстом: неверные учётные
     данные → «Неверный логин или пароль»; ошибки из БД приходят в формате
     `[код] Русский текст` (коды: registration_closed, invalid_username,
     username_taken и другие — список в docs/STATE.md) — парсить код, текст
     показывать пользователю; всё прочее → UnexpectedFailure с общим текстом.
     На маппинг — отдельные юнит-тесты.

3. **AuthController** (`lib/features/auth/presentation/controllers/`):
   заменить стаб. Состояние должно нести профиль (например, sealed-класс:
   unknown / unauthenticated / authenticated(UserProfile)). Подписка на
   `onAuthStateChange`, восстановление сессии при старте. Существующий
   redirect роутера сохранить рабочим (он читает `authControllerProvider`).
   Добавить guard роли: `/admin` доступен только `UserRole.admin`, иначе
   redirect на `/`; пункт «Админка» в навигации скрывать у студентов
   (число веток StatefulShellRoute при этом не ломать — допустимо скрывать
   destination только визуально или перестраивать shell по роли, выбери
   аккуратное решение и опиши его).

4. **UI** (экраны уже свёрстаны — довести): валидация логина
   `^[A-Za-z0-9_]{3,20}$` и пароля (≥8 символов) с русскими сообщениями,
   индикатор загрузки на кнопках, показ `Failure.message` (SnackBar или
   inline). Экран регистрации: при закрытой регистрации
   (`is_registration_open` = false) — сообщение и заблокированная форма.
   Кнопка «Выйти» на экране профиля. Все строки — через l10n (ARB).

5. **Тесты**: юнит — use case'ы, репозиторий (мок datasource через mocktail),
   маппинг ошибок, контроллер; виджет — формы входа/регистрации (валидация,
   отображение ошибок), guard админки. Существующие тесты роутера обновить
   под новый контроллер. Цель покрытия domain/data — 80%+.

6. **Не делать**: UI сброса пароля (это админка, этап 8), email-подтверждение,
   «запомнить меня» (сессию и так хранит supabase_flutter), изменение схемы БД.
