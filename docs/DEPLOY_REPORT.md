## Расхождения

### 1. В базе была одна задача, хотя задание исходило из пустой

Задание велит остановиться и спросить, если задач больше нуля. Задача
нашлась одна — ручная, опубликованная, с ответом, не из банка. Импорт
её не затрагивает (удаляются только строки с `origin = 'fipi'`), дамп
сделан до заливки, так что решение было безопасным в обе стороны.
Она осталась как была.

Следствие — шесть пунктов `import_checks.sql` дают +1. Число не подгонялось:
вместо этого те же шесть пунктов прогнаны с разбивкой по `origin`, и по
банку они сходятся точно.

### 2. Заголовки с `_16`, `_8`, `_2` — не у заданий номера 14

Пункт приёмки 4 ждёт их у заданий номера 14. Фактически индексы оснований
есть у **47** заголовков (`_16` — 18, `_8` — 3, `_2` — 29), и **ни один**
из них не принадлежит заданию номера 14.

Причина не в импорте: банк ФИПИ номера заданий не публикует вовсе
(в `metadata.json` так и записано — «фильтр qpos пуст»). Номер восстановлен
по спецификации ЕГЭ-2026, и задачи на системы счисления под 14-й номер
не попали — у них номера нет совсем. Проверять пункт нужно по этим 47
заголовкам. Существо проверки выполнено: числа не слипшиеся, например
«Вычислите значение выражения 9E\_16 – 94\_16.»

### 3. Объём вложений — 427,5 МБ, а не «около 500 МБ»

1571 файл занимает 427,5 МБ — 43% бесплатного гигабайта. В каталоге
выгрузки лежит 784 МБ, но 790 файлов там — хвосты прошлой загрузки: после
перевыпуска выгрузки файлы перенумерованы (`_1` → `_2`), старые остались
рядом и байт в байт совпадают с нужными. Импорт и заливка идут по
`tasks.json`, поэтому в Storage они не попали.

### 4. Применённых миграций было семь, а не шесть

`20260918090000_fix_audit_files_count` уже был в боевой базе (проверено по
телу функции `admin_upsert_task` в дампе). На порядок применения это
не повлияло.

### 5. У представления `task_articles` остались права на запись

`authenticated` имеет на нём `INSERT/UPDATE/DELETE` — это права по умолчанию,
которые Supabase выдаёт на новые объекты в `public`. Дыры здесь нет:
представление соединяет три таблицы и потому не обновляемо, а `anon` доступа
к нему не имеет вовсе. Но права стоило бы снять отдельной миграцией, как это
сделано для `task_themes`.

### 6. Ручная задача осталась без темы

`e24-longest-run` заведена до появления таблицы тем, а триггер
`trg_tasks_have_theme` срабатывает только на вставку. В навигации по темам
она не появится, пока ей не проставят тему.

## Что осталось

* **Задачи не опубликованы и публиковать нечего**: банк ФИПИ ответов
  не отдаёт, а без `reference_verified_at` публикацию запрещает сама схема.
  Ученик по-прежнему видит одну задачу — ручную. Чтобы банк заработал для
  учеников, нужны ответы и эталонные решения.
* **Навигации по темам в интерфейсе нет** — сделана только серверная часть.
* Права на запись у `task_articles` (расхождение 5) и тема для ручной задачи
  (расхождение 6) — отдельными миграциями.
