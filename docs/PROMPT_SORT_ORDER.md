# Задание: порядок сортировки в запросах клиента

## Зачем

В `postgrest` для Dart (2.9.1) `order()` по умолчанию сортирует **по
убыванию**: `ascending` по умолчанию `false`, в документации пакета это
сказано прямо. Клиент писался с расчётом на SQL, где по умолчанию
возрастание. Поэтому каталог задач начинается с номера 26, а внутри номера
задачи идут от «Я» к «А». Файлы задачи идут в обратном порядке, и список
статей справочника тоже перевёрнут.

Задача — задать порядок явно во всех запросах клиента и закрепить его
тестами, которые проверяют настоящий запрос. Схема БД и боевая база не
меняются.

Прочитать перед работой: `CLAUDE.md`, `docs/STATE.md` (контракты кода,
«Чего ещё нет» — пункт про порядок сортировки), `docs/CLIENT_ANSWERS_REPORT.md`
(раздел 5 — как нашли).

## Что сделать

### 1. Явный порядок во всех запросах

Каждый вызов `order()` в `lib/` — с явным `ascending`:

- каталог: `ege_number` по возрастанию, затем `title` по возрастанию;
- файлы задачи: `sort_order` по возрастанию;
- номера для фильтра: `ege_number` по возрастанию;
- статьи справочника: `level` по возрастанию, затем `title` по возрастанию.

Вызовы, где порядок уже задан явно, не трогать.

### 2. Тесты на настоящий запрос

Виджет-тесты работают на заглушках репозитория и порядок не ловят.
Нужны тесты datasource: настоящий `SupabaseClient` с `httpClient` из
`MockClient` (`package:http/testing.dart`). Он запоминает запрос и
отвечает `[]`. Тест проверяет параметр `order` в адресе, например
`order=ege_number.asc.nullslast,title.asc.nullslast` для каталога.
Свой тест — на каждый из четырёх запросов из п. 1. Существующие тесты
не ломать.

### 3. Проверка на боевой (только чтение)

Тот же способ, что в прошлом задании (`CLIENT_ANSWERS_REPORT.md`,
раздел 4). Временный тест с токеном сервисного аккаунта
(`tools/content_client.py`, `ContentClient().token`) и HTTP-клиентом,
который пропускает только GET. Через настоящий
`SupabaseTasksRemoteDataSource` получить каталог и показать: первая
задача — номера 1, номера не убывают, внутри номера названия идут по
алфавиту. Напечатать номера и первые буквы названий, а не условия.
После прогона временный тест удалить, в коммит он не идёт. Значения
переменных окружения не выводить.

### 4. Документация

`docs/STATE.md`: убрать из «Чего ещё нет» пункт про порядок сортировки и
кратко записать в разделе о доработке, что порядок задан явно и почему.
Остальное не переписывать.
