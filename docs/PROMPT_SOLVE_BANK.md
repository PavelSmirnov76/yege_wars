## Зачем

На боевой базе 2475 заданий банка, и все они черновики. ФИПИ не публикует
ответы, а без ответа и сверенного эталона (`reference_verified_at`) схема
не даёт опубликовать задачу. Ученик видит одну задачу из 2476.

Нужно решить задачи **кодом** и подтвердить каждый ответ у первоисточника:
`solve.php` банка только говорит, верен ли присланный ответ. Ответ
не угадывается и не подбирается перебором.

Начинаем с покрывающего набора: 203 задачи, по одной на каждый вариант
формулировки каждого номера КИМ (`kim_coverage.json`, поле `task_ids`).
Заливка ответов в базу — следующее, отдельное задание.

Прочитать перед работой:

- `CLAUDE.md` и `docs/STATE.md`, раздел «Импорт банка ФИПИ…»;
- `~/projects/ege-informatics-2027/README.md`;
- `~/projects/ege-informatics-2027/parser/fipi_client.py`, метод
  `check_answer`.

## Правила

### Условие

Текст (`condition_text`) получен из HTML, и часть разметки при этом теряется.
Первоисточник — `tasks/<id>.html`. Если решение не сходится, причина чаще
в неверно прочитанном условии, чем в алгоритме.

- **Степени и индексы** размечены `<sup>`/`<sub>`. Уже был случай, когда
  `2<sup>21</sup>` превращалось в `221`. Подозрительное число сверить с HTML.
- **Данные на картинке** (граф, таблица расстояний, таблица истинности) в
  тексте отсутствуют. Картинку открыть из `assets/images/` инструментом
  чтения файлов и перенести данные в код вручную.
- **Данные в файле.** Прежде чем писать алгоритм, распечатать первые строки
  и убедиться, что формат разобран верно.
- **Таблицы** читать из HTML: в тексте ячейки слипаются.
- **Задачи 20 и 21** решать вместе с условием родителя (`parent_id`).
- Если текст расходится с HTML или с картинкой, верить HTML и картинке,
  а расхождение записать в отчёт. Это брак выгрузки, его чинят у источника.

### Эталонное решение

- Только стандартная библиотека, совместимость с Python 3.9 (без `match`).
  Без сети.
- Файл открывается **по имени, без пути**: `open('<id>_N.txt')`,
  `zipfile.ZipFile('<id>_N.zip')`. Запуск — с рабочим каталогом
  `assets/files/`. Так же файлы лежат и на платформе, поэтому эталон потом
  пройдёт сверку там без правок. Архив читается прямо из zip, без распаковки
  на диск.
- `.rar` стандартная библиотека не читает. Такой файл распаковать через
  `bsdtar` в `work/<short_id>/`, эталон читает оттуда. Каждый такой случай
  указать в отчёте: на платформе эталон без правки не запустится.
- На CPython эталон работает не дольше 20 секунд: Pyodide на платформе
  медленнее в 1,5–3 раза, а её таймаут — 60 секунд. Более медленные
  эталоны перечислить в отчёте.
- Печатает ровно ту строку, что лежит в `answer`.

### Проверка ответа в банке

- Запросы к `solve.php` идут только через `FipiClient.check_answer`
  с `delay` не меньше 0,5 с, то есть не чаще 2 запросов в секунду.
  Запускать под `.venv/bin/python`.
- **Каждый** вызов `check_answer` дописывается строкой в журнал
  `solve_log.jsonl` в корне выгрузки: время, `task_id`, `short_id`,
  отправленный ответ, код банка. Журнал только дописывается. По нему
  проверяются число запросов и то, что ответ действительно подтверждён.
- На задачу — не больше двух вызовов: ответ и, если не сошлось, ещё один
  после исправления решения. Неверный формат ответа тоже тратит попытку,
  поэтому формат выясняется на пилоте. После двух «неверно» задача остаётся
  нерешённой. Перебирать значения и варианты нельзя: команду `answers`
  из `parser/main.py` не запускать.
- Коды банка: `3` — верно, `2` — неверно, `1` — засчитано без проверки,
  `0` — ответ не принят. Подтверждён только ответ с кодом `3`.
- Если `ege.fipi.ru` не отвечает, остановиться и сказать пользователю
  (скорее всего, выключен VPN). Обходных путей не искать.
- Решать можно параллельно, субагентами по номерам КИМ, если это даёт
  выигрыш. Но `solve.php` вызывается только из одного процесса: иначе
  лимит частоты и журнал разъедутся.

### Результат и его сохранность

`solutions.json` в корне выгрузки — массив записей:

```json
{
  "task_id": "0011FF4F34E082534C60E5C3716A2AB5",
  "short_id": "48F84F",
  "kim_number": 13,
  "answer": "9883255254",
  "answer_format": "string",
  "reference_solution": "import ipaddress\n…",
  "answer_explanation": "Сеть 98.80.0.0/14, наибольший адрес узла 98.83.255.254.",
  "verified": true,
  "verify_code": "3",
  "attempts": 1
}
```

- `answer_format` берётся из таблицы выше, а не выбирается самостоятельно.
- `answer_explanation` — 1–2 предложения о том, как получен ответ. Если
  данные взяты с картинки или из файла, это должно быть видно из текста.
- `verified: true` — только при коде `3` в журнале с тем же ответом.
- Нерешённая задача тоже попадает в файл: `"answer": null`,
  `"verified": false`, причина — в `answer_explanation`. Четыре задачи
  с развёрнутым ответом попадают туда же с причиной «развёрнутый ответ».
- **Файл перезаписывается после каждой задачи** (запись во временный файл,
  затем переименование). Если сессия оборвётся, новая продолжит с того же
  места и не будет заново проверять подтверждённые задачи.
- UTF-8, `ensure_ascii=False`.

### Скрипт проверки

`parser/check_solutions.py`: стандартная библиотека, запуск под системным
`python3`, сеть не нужна. Он проверяет:

1. `solutions.json` — валидный JSON, `task_id` уникальны, все из набора;
2. у каждой записи с ответом эталон, запущенный из `assets/files/` с
   таймаутом 60 с, печатает `answer` (сравнение по правилу формата из
   таблицы выше);
3. `verified: true` ⇔ в `solve_log.jsonl` есть код `3` для этого `task_id`
   с тем же ответом;
4. `verified: false` ⇒ `answer` равен `null`;
5. число вызовов в журнале не больше удвоенного числа взятых задач;
6. печатает сводку по номерам КИМ и в конце `SOLUTIONS OK` или список
   нарушений.

## Отчёт

`docs/SOLVE_REPORT.md` в репозитории `yege_wars` (не в выгрузке): он под
git, и итог не потеряется. **В отчёте нет ни одного ответа и ни одного
эталона**: задачи называются по `short_id`.

Отчёт ведётся по ходу работы, а не пишется в конце. Он обновляется на
каждом СТОПе и после каждого номера КИМ, чтобы пережить обрыв сессии.
Разделы:

1. **Состояние**: дата, сколько взято, решено, подтверждено, не решено,
   сколько ушло запросов. Обновляется.
2. **Журнал решений**: каждый вопрос пользователю и его ответ — дата, вопрос,
   варианты, выбранный вариант. Запись делается сразу, как пришёл ответ.
   Размышления не записываются, только вопросы и решения.
3. **Формат ответов ФИПИ**: что выяснилось на пилоте (разделители, порядок
   чисел, регистр), с `short_id` задач-примеров.
4. **Итоги по номерам КИМ**: таблица «номер — взято — подтверждено —
   не решено — запросов».
5. **Нерешённые**: `short_id`, номер, причина.
6. **Расхождения выгрузки**: где текст расходится с HTML или с картинкой.
7. **Эталоны с оговорками**: rar, дольше 20 секунд.
8. **Отступления от задания** и **найдено вне задания**: всё, что не
   исправлялось, — сюда, а не только в чат.
9. **Проверки**: вывод `check_solutions.py` дословно.

## Порядок работы

### Часть 1. Пилот

1. Проверить доступ: `ege.fipi.ru` отвечает, `.venv/bin/python` импортирует
   `httpx`.
2. Выбрать 10–12 задач набора так, чтобы были представлены: краткий ответ
   без вложений, выбор ответа, файл в zip, файл ods, картинка, ответ из
   нескольких чисел (номера 25–27), задача с родителем (20 или 21),
   последовательность.
3. Решить, проверить, записать в `solutions.json` и журнал. Написать
   `check_solutions.py` и прогнать.
4. Завести отчёт, заполнить «Формат ответов ФИПИ».

### СТОП 1

Коротко в чат и в отчёт: сколько подтверждено из пилота, сколько ушло
запросов, что выяснилось о формате ответов, вывод `check_solutions.py`.
Спросить пользователя через вопрос с вариантами: продолжать ли на весь набор.
Без ответа «да» дальше не идти.

**Стоп-условие и на пилоте, и дальше.** Остановиться и доложить, если:
- среди уже сделанных задач подтверждено меньше 80%;
- банк начал отвечать кодами `0`/`1` или ошибками HTTP;
- журнал разошёлся с `solutions.json`.

Правила работы самостоятельно не менять.

### Часть 2. Весь набор

Идти по номерам КИМ, а не подряд: внутри номера механика повторяется.
Сначала задачи без вложений, затем с файлами, затем с картинками. Методика
по темам — `handbook/<код КЭС>.md`. После каждого номера обновить отчёт.

### СТОП 2

Прогнать `check_solutions.py` → `SOLUTIONS OK`. Скопировать
`solutions.json` и `solve_log.jsonl` в
`~/backups/yege_wars/solutions-<ГГГГММДД>/`: других копий у ответов нет.
Отчёт — финальный. Коротко в чат: итог и где что лежит. Спросить про коммит.

### Часть 3. Git (только после подтверждения)

В коммит `yege_wars` идут `docs/SOLVE_REPORT.md`, этот файл и `CLAUDE.md`.
Коммит на русском, в стиле истории. Файлы
добавлять по именам, перед коммитом проверить `git status`: в индексе нет
`reference/`, `supabase/seed/local/`, `supabase/.env.local`. Ничего
из выгрузки в git не идёт.
